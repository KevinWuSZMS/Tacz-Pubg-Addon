# 地图保护与改动复原

2026-10-20 改为保护期与改动日志。旧整图备份、哈希扫描和逐区块复原已从运行代码移除。

```text
创建地图 → 保护期 → 刷新本地图物资 → 准备参赛人员（仍保护）
         → 对局开始，记录改动与掉落物 → 对局结束，清理物资、锁定地图
         → 只复原改动位置 → 保护期
```

保护覆盖地图完整方块列：`ceil(minX) ≤ x < floor(maxX)`、`ceil(minZ) ≤ z < floor(maxZ)`，包括该维度全部建造高度。

- 服务端在 `LevelChunk.setBlockState` 写入前拦截保护期修改；挖掘、放置、右键、爆炸和跨边界活塞另有提前拦截。计划方块/流体更新和方块实体 tick 在保护期暂停。
- 对局内首次修改一个位置时复制原始方块状态和方块实体 NBT。同一位置再次修改保留第一份原始值；放置新方块也记录原先的空气。
- 容器原始数据在地图创建及区块加载时复制。内容修改、卸载及结束时检查容器数据，把仅库存发生改变的位置加入日志。保护期阻止原版容器写入及漏斗跨边界传输，地图外的物品实体仍按原逻辑运行。
- 管理员结束、自然结算或开局准备取消都会回到保护流程；无改动则直接完成。改动位置按区块分组，每批最多 4096 个位置、约 8 毫秒服务端预算，最多提前请求 4 个相关区块。区块加载使用 Minecraft 自身异步管线，世界修改留在服务端线程。
- 单人游戏暂停或切出窗口时，通过集成服务器的 `tickPaused` 继续复原；世界正常 tick 和自动开局仍保持暂停。
- 绿色 BossBar 显示已复原位置/全部改动位置，以及涉及的区块数。没有整图扫描或哈希比较步骤。

重叠地图不能同时开局或恢复。同一物理位置处于某张地图的对局范围时，由这场对局记录并在结束时复原；其他重叠地图保持待用。

改动记录保存在主世界 `data/tacz_pubg_map_changes.dat`，随 Minecraft 的正常存档保存。重启后不会续开对局，会重新执行未清理日志；完成日志保留到下一局，支持在区块与 SavedData 保存顺序不一致时幂等重放。这不是独立的每次方块改动强制落盘事务，进程强杀仍受 Minecraft 最近一次保存进度限制。

失败时保留原始日志、锁定地图并阻止开局。OP 2 可使用：

```mcfunction
/pubgdebug mapJournal status
/pubgdebug mapJournal retry <mapId>
```

玩家、动物、车辆、地面物资等实体，以及时间、天气、群系、物品概率和地图配置不属于方块改动日志。地图复原不会替这些内容创建整图快照。

地面物资使用独立的对局清理机制：开局前按原区域概率和档位刷新本地图内的物资，等刷新完成再准备参赛人员。刷新只请求相关物资区域的区块，每 tick 最多请求两个；取消准备或结束时撤销待刷新任务。

原掉落物及本局刷新的物资带有持久化物品组件，拾取、拆分、容器搬运和普通掉落物转为地面物资时保留。与未标记物品不混堆。结束后清除地图内地面物资，并让该局原物品在所有持有者处失效；合成、酿造等产物不继承原物品标记，不追踪转换链。失效记录保存在 `data/tacz_pubg_round_loot.dat`，覆盖离线玩家、未加载容器和区块，重启时结束未完成的物资轮次。未加载地面物资在重新加载时清除。

物资区域选点和保存均由服务端限制在地图内，同一次选择必须完整位于同一张地图内。历史区域不删除；开局刷新只取当前地图内的有效楼层。Xaero 大地图、小地图显示该维度的全部地图，编辑草稿替换其对应地图的显示。

旧机制源码与原 JAR 保存在 `logs/source-backups/retired-map-restore-20261020-152439/`。旧存档归档及旧维护记录保留原样，新机制不读取或执行它们。已有地图首次启用新版本时，以当时的地形进入保护期；更早发生且未记录的损坏不会由新日志追溯恢复。创建地图不再生成整图备份，因此原先的备份进度条需求由当前改动复原进度条承接。

验证：离线首次修改去重、六区块改动范围、原始 NBT 复制、容器记录往返、重启恢复、损坏数据保留及实际 Minecraft 方法签名检查。未启动客户端或服务器，游戏内视觉、第三方模组绕过标准入口的行为与实际耗时尚未实测。
