# 当前枪包的配件模型兼容审查

审查日期：2026-10-18（Asia/Shanghai）。对象为工作区 Minecraft 1.21.1 / TaCZ NeoForge 1.1.8-hotfix-r7 当前安装的八个 ZIP 和默认包目录。本次只读资源和匹配源码，不改运行包、不执行 Lua、不启动 Minecraft。这里讨论游戏资源适配，不涉及真实枪械改装。

## 结论

**允许安装、数值生效、模型正确、动画正确是四个不同条件。** 放宽附件 ID 白名单或枪械允许槽位，只解决安装权限，不会给枪模型补出安装骨骼、转接模型、瞄准定位或换弹动画。

当前读取到 **247 个附件索引**：scope 76、grip 34、stock 42、muzzle 54、extended_mag 27、laser 14。213 个 display 有 model/texture，34 个没有独立模型；45 个 display 指定 adapter，12 个 index 声明 hidden。附件 index/data/display 路径未发现内容冲突；其他资源重复路径不在此结论范围内。

这里的 model/texture 数量是引用声明数，不能等同于全部资源有效。额外发现 hidden 附件 classicr:muzzle_silencer_default 引用 classicr:attachment/muzzle_silencer_default_geo，但当前安装包中没有 assets/classicr/geo_models/attachment/muzzle_silencer_default_geo.json；它应列为资源不完整并保留隔离。本次未改包或补模型，尚未判定实际运行是否会触发该隐藏资源路径。

扫描到 431 个枪械索引，其中 424 个有可解析的 display/model 引用；以下挂点统计仅针对这 424 个正常模型，不把缺资源索引说成已在游戏注册成功，也不代表已完成全部动态资源验证。

| 枪模型节点 | 有该节点 | 无该节点 | 当前数据允许该类型但无该节点 |
| --- | ---: | ---: | ---: |
| scope_pos | 365 | 59 | 3 |
| muzzle_pos | 357 | 67 | 7 |
| grip_pos | 241 | 183 | 8 |
| stock_pos | 197 | 227 | 23 |
| laser_pos | 259 | 165 | 3 |

最后一行不能理解为扩容全部失效：扩容通常靠枪体自己的 mag_standard、mag_extended_1/2/3 等骨骼切换。相反，这说明不能把地面上有弹匣模型当成它装到枪上也会沿普通附件挂点渲染的证据。

当前已有例子：tacz:aug 的 allow_attachment_types 有 grip，但正常模型没有 grip_pos；tacz:m1911 允许 scope，但正常模型没有 scope_pos。单看允许列表或槽类型会把这些组合判得过于乐观。

## r7 实际如何装出模型

匹配的 [BedrockGunModel 源码](../downloads/tacz/r7-source-inspection/com/tacz/guns/client/model/BedrockGunModel.java)提供以下机制：

- 普通附件按类型对应的节点挂载，例如 scope_pos、muzzle_pos、grip_pos、stock_pos、laser_pos；瞄具需要 scopePosPath 来参与独立渲染与瞄准路径。
- 安装附件可能隐藏枪体原有的 type_default；瞄具还影响 mount、carry、sight、sight_folded 等显示分支。因此新模型既可能看不见，也可能把原本结构隐藏掉。
- display.adapter 是**枪模型已有 attachment_adapter 节点下的子节点名称**，程序只决定该子节点是否显示。它不凭空生成转接器，也不是任意两种资产之间的自动坐标转换。
- 扩容等级切换枪体已有 mag_extended_N；换弹可能另渲染 additional_magazine。附件自己的独立模型并不取代这些枪体结构。

完整匹配 sources JAR：[tacz r7 sources](../downloads/tacz/tacz-neoforge-1.21.1-1.1.8-hotfix-r7-sources.jar)，内部证据入口：

- com/tacz/guns/client/model/functional/AttachmentRender.java，35–53 行：没有 attachment model 或 texture 时，枪上不绘制该附件。
- com/tacz/guns/client/model/GunModelConstant.java：_pos、_default、attachment_adapter、magazine、mag_extended_1/2/3、additional_magazine 等约定。
- com/tacz/guns/client/model/BedrockAttachmentModel.java：scope_view、scope_view_N、ocular、ocular_sight、ocular_scope 等瞄具节点及镜内渲染路径。

独立图标或地面模型正常，只说明 display 可以用于独立展示；不等于该模型能在任意枪上安装后正确呈现。

## 各分类的视觉和行为边界

### scope：倍率相同也可能装不齐

枪侧 scope_pos 与附件侧 scope_view/ocular 共同决定眼位和镜内表现。相同倍率不能替代这些几何数据；更不能只改变统计数值就修正遮挡、镜片模板和手枪安装高度。

当前 tacz:sight_acro_pistol 的 scope_view pivot 是 [0, 0.8125, 14]，tacz:sight_acro_rifle 为 [0, 1.5625, 11]；两者倍率都为 [2]，但模型定位不同。这里是模型局部坐标，不是世界坐标，也不应作为真实器材尺寸。

cbrg:canted_sight 仍占唯一 scope 槽，scope_view 带 [0,0,-45] 旋转；它不是自动增加一个独立副镜槽。tacz:scope_hamr 同时有 scope_view 与 scope_view_2，以及 ocular_sight/ocular_scope_2，是多视图资源；不能通过替换一个倍率字段把任意镜变成等价组合镜。

tacz:scope_aug_default 为 hidden，show_mount=false，是作者特定设计。ccrp:scope_xm157_black 的 data.extras 包含 advanced_rendering 与 thermal_imaging；这些自定义声明是否运行仍取决于对应消费者，不代表当前 TaCZ 核心已经对任意枪提供完整热成像。

建议：通用候选镜先匹配枪侧挂点，再检查瞄具视角、导轨显示分支和模型坐标；内置/隐藏镜、组合镜和特殊渲染镜保留显式适配。

### muzzle：默认枪口、刺刀与专用长枪管不可混为一类

该槽同时容纳消音/补偿附件、刺刀和作者专用结构。cib:qbz191_bayonet、tacz:bayonet_m9 带 melee 数据并设 show_muzzle=true；不能只按消音器逻辑隐藏原枪口，还要核对近战动画及枪上实际节点。

tacz:deagle_golden_long_barrel 使用特定长管模型和黄金 Deagle 纹理，应保留专用映射；它不是全枪通用的数值增益模块。hamster:whip 只有 adapter=whip，没有独立 model，依赖枪体已有的鞭子结构。

CBRG 五种枪口附件还各带不同 adapter 名，例如 suppressor_rifle_adapter、suppressor_pistol_adapter；换到没有对应子节点的枪，不能假定转接外观自动出现。还需核对 muzzle_default、muzzle_flash 与附件 show_muzzle。

### grip：包含握把、激光器、内置枪托和下挂武器

同类握把尺寸不同，原有手臂骨骼和动画不会因为安装白名单放宽就自动重新对齐。枪可能没有 grip_pos，或者手仍抓在原护木位置。

特别需要隔离：

- cbrg:laser_sight 的 type=grip，display 却有激光参数；cib:grip_191、tacz:grip_vertical_ranger 也属于 grip 且带 laser。不能把名称含 laser 或有 laser 参数就全部迁移到 laser 槽。
- ccrp:stock_191_default 实际 type=grip、hidden=true，display 只有 adapter=qbz_stock，无独立模型；名字不能代替类别与挂点核验。
- ccrp:weapon_m203 的 display 无 model，其 data.extras.under_barrel 指定 gun=tacz:m320、gun_display_namespace=ccrp、gun_display_prefix=m203_。作者中文描述明确是为 m16a4 设计，并说明装 TACZ:Arcana 时才能启用下挂榴弹。它是带附属接入语义的武器模块，不是普通握把。
- suffuse:grip_m203 有普通三维模型和握把数值，但没有上面的 under_barrel extras。相似名称不能证明两者拥有相同下挂武器功能。

建议：只把明确普通握把作为第一批扩展；带 under_barrel、内置 adapter、隐藏结构或额外行为的资源保留专门映射。

### stock：包含托腮板、脚架、调节件和盾牌技能

当前 stock 槽并不只表示完整枪托。cbrg:cheek_pad 是托腮板；ccrp:m14_bipod 是 adapter=m14_bipod 的模型分支；ccrp:stock_192_gasknob 使用 adapter=gas_knob，data 改 rpm/recoil，不能按普通枪托泛化。

tacz:oem_stock_heavy/light/tactical 没有独立 model，分别显示枪体内同名 adapter；常见 AR 风格枪托则常用 ar_stock_adapter。枪体没有该节点时不会凭空补齐。tacz:stock_heavy_spas_12 和 stock_tactical_spas_12 的模型按 SPAS12 结构设计，默认保留专用关系更合理。

ccrp:flash 在 stock 槽，但作者名称为“[盾装]战术爆闪模块”，描述用于 FORT | VantVM 战术突击盾，并将近战换成爆闪；data.melee.effects 包括 glowing/darkness/weakness/slowness，display.adapter=flash。这是当前最明确不应因 stock 类型相同而开放给所有枪的附件之一。

### extended_mag：等级标记、弹药效果、转换套件混用

当前27项至少分三类：

1. 通用等级标记，如 tacz:extended_mag_1/2/3、light_*/sniper_*/shotgun_*，大多没有附件独立模型；枪侧 extended_mag_ammo_amount 决定容量，模型和动画依赖枪本体。
2. CBRG 快换/扩容三项，自己的 display 有模型，但 data 主要只有 extended_mag_level=1/2/3。当前 AK47、HK416D 的三个容量值为 [30,42,40]；同一 level 在不同枪的含义由枪自身表和脚本决定，不能据名称直接推断统一百分比或统一换弹时间。
3. 类型复用：tacz:ammo_mod_fmj/hp/he/i/slug、ccrp:ammo_mod_hap、classicr:ammo_mod_rubber_bullet/snake_shot 等在这个槽里改变弹药效果；cib:change 是作者明确标出的枪械转换套件。它们不是普通“弹匣大小”配件。

当前 HK416D 动画有 reload_tactical_xmag_1/2/3 和 reload_empty_xmag_1/2/3；AK47 使用共享 xmag 动画；SPAS12 使用 intro/loop/end 装填阶段；P90 正常模型没有 mag_extended_1/2/3，容量表还是 [50,50,50]。这些差异无法靠给所有枪开放 extended_mag 权限统一解决。

建议：扩容等级只在枪已定义容量、对应模型/装填脚本有意义时放宽；转换套件、特殊弹药、速度装填器、管式装填条等独立审查，不全槽通用。

### laser：安装方向和发射骨骼也要检查

14项索引 type=laser，但全部附件里有17个 display.laser，另外3个在 grip 槽。激光模型有自己的 laser_beam 骨骼，枪侧 laser_pos 还可能有旋转：例如 HK416D 的局部旋转为 [0,0,90]，AUG 为 [0,0,-45]。

tacz:laser_compact 还要求 adapter=laser_adapter。ccrp:laser_eotech_ogl/laser_peq15 的 extras 另有 flashlight 参数，自定义手电行为不能仅凭看到参数就宣称已启用。

建议：分开校验槽位、枪侧安装方向、附件侧发射点、adapter 和附属行为；模型可见不等于光束方向及第一/第三人称效果正确。

## LOD与动画不能遗漏

当前部分原包的低模挂点明显少于正常模型：

| 枪型 | 正常模型关键挂点 | LOD关键挂点 |
| --- | --- | --- |
| tacz:ak47 | stock/muzzle/scope、adapter、mag_extended_1/2/3 | scope_pos |
| tacz:hk416d | scope/muzzle/grip/stock/laser、adapter、扩容骨骼 | muzzle/laser/scope/grip |
| tacz:aug | scope/laser/muzzle、扩容骨骼 | laser_pos |
| tacz:spas_12 | scope/muzzle/stock、adapter、扩容骨骼 | scope_pos |

这些是当前文件的静态事实，不是本轮新增问题。扩大适配后，应分别记录第一人称、近距离第三人称/地面高模和远距离低模结果，不能把高模挂点存在推导成全部距离都能看到附件。

标准地面平放与选择轮廓只处理展示，并不能证明装枪动画兼容；高模、LOD、换弹第二弹匣、默认护木/枪托隐藏分支与手臂动作需要按模型资源链核对。

## 建议给兼容矩阵增加的维度

每个“枪型×附件”组合应区分：原有兼容、仅权限可扩、显示需校准、缺挂点、依赖adapter、依赖专用动画/脚本、依赖额外模组、专用或转换附件。

至少记录 gun_id、attachment_id、index.type、枪侧正常/LOD节点、display.model、display.adapter、scope多视图、show_mount/show_muzzle、枪侧容量表、特殊extras、作者hidden及审核结果。不要把 type 相同直接当成绿色兼容结论。

第一批较适合扩大的是模型结构清晰的普通瞄具/握把/常规枪口件；没有正确挂点时仍须保持“待模型适配”。以下资源默认保留专用白名单：转换套件、盾牌技能、下挂武器、作者内置/隐藏结构、依赖特定adapter或特定枪身替换部件。
