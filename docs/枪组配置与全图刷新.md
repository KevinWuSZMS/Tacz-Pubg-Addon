# 物品配置与全存档物资刷新

适用 Minecraft 1.21.1 / NeoForge 21.1.259 / TaCZ r7 / `tacz_pubg`。2026-10-19 更新。为兼容已有链接，保留本文件原文件名；当前已取消旧版组合模板。完整更新见[物品生成与交互更新说明](物品生成与交互更新说明.md)。

## 配置和刷新

```mcfunction
/pubgdebug config
/pubgdebug itemRespawn
/pubgdebug itemRespawn status
```

需要权限等级 2。`config` 编辑本存档的物品和通用设置；保存成功后才生效。`itemRespawn` 按保存的配置刷新**整个存档所有维度的全部已标记区域**，与标记棒当前临时选区无关，也不要求持棒。未加载区域保留待处理任务，等区块自然加载，不强制加载全图。

## 四个配置入口

顶部统一为“基础设置 / 原始/实验性 / 创建地图 / 创建游戏”，沿用独立 HTML 原型的分工和布局。游戏中使用原生按钮、真实物品图标、Xaero 地形及服务器回包，不加载 HTML；网页原型继续独立保留，二者无运行时联动。

基础设置集中放置类别百分比、搜索列表、当前物品的权重/数量及逐枪配弹；通用生成参数从同一入口展开。宽屏同时显示更多面板，窄屏使用滚动内容与配弹子页。四入口切换保留各自草稿，包括暂未输入完整的数值；放弃、关闭和重新加载时明确处理草稿。

## 原始/实验性

`/pubgdebug config → 原始/实验性` 为以下八项各提供独立选项，使用滚动列表适应窗口高度：

| 类别 | 初始 | 实验性调整 |
| --- | --- | --- |
| 平衡调整 | 枪包原伤害、后坐力和散布 | 原研究算法的 423 把有效枪械候选 |
| 瞄具 | 原枪包安装规则与基础生成权重 | 逐枪 PUBG 瞄具规则；独立生成池只保留9种CBRG经典瞄具（含侧瞄） |
| 子弹 | 原枪包供弹ID与基础生成权重 | 420把固定映射；独立弹药池只保留18种批准供弹，配套弹药仍读每枪实际弹种 |
| 枪口 | 原枪包规则与基础生成权重 | 普遍配件保留权重；专用配件最多0.01，兼容0枪者为0；可随兼容枪生成 |
| 激光 | 原枪包规则与基础生成权重 | 独立生成池只保留选定的CBRG激光，不与GRIP型握把混淆 |
| 握把 | 原枪包规则与基础生成权重 | 与枪口同样按实际支持枪数降权及配套生成 |
| 枪托 | 原枪包规则与基础生成权重 | 与枪口同样按实际支持枪数降权及配套生成 |
| 弹匣 | 原枪包规则与基础生成权重 | 只生成定稿九件；292枪按名单适配，26把DMR双族；等级1/2/3与快速换弹 |

各项独立生效。平衡实验中386把采用批准角色目标，38把保留此前实验逻辑；平衡、瞄具、子弹和弹匣的原生数据设置通过资源重载/同步生效。枪口、激光、握把、枪托实验在本轮实现生成池筛选及专用配套，不改它们已有的属性数值。详细运行规则见[弹药合并与枪类平衡实装](弹药合并与枪类平衡实装.md)。平衡研究见[分析与前后图表](枪械属性分布与20生命平衡方案.md)。

选择只改草稿；点击“保存全部”提交，等服务器应用完成通知。有效选项改变时，经过 TaCZ 原生资源重载及同步；原枪包文件不改动。方案按存档保存，原来的 `researched` 配置迁移为平衡、瞄具均选实验性，其余选初始。此前首次研究方案开启时扩大原瞄具槽的行为已撤回。

## 瞄具实验性调整的逐枪规则

[完整图文装配表](compatibility/pubg-scope-policy.html)覆盖当前424把枪，每行提供枪械图片、名称、ID、原始瞄具能力、PUBG映射/类推依据和9种CBRG瞄具的允许状态；[表格说明](compatibility/pubg-scope-policy.md)区分官方规则、历史数据与项目类推。

规则首先检查**原始** `allow_attachment_types`：没有 scope 的71把枪保持关闭，不新增槽，不因枪类或 PUBG 对应型号而越过原始限制。有槽的枪才执行逐枪瞄具白名单。非 PUBG 枪按相近枪类保守类推并明确标注；未来未入表的新枪维持初始规则，需重新核对后再扩展。

本次针对 Classic BattleRoyale Gun Pack 的9个scope资产：

| 瞄具 | 资产 ID |
| --- | --- |
| 红点 | `cbrg:red_dot` |
| 全息 | `cbrg:holographic_sight` |
| 侧瞄 | `cbrg:canted_sight` |
| 2倍镜 | `cbrg:2x_scope` |
| 3倍镜 | `cbrg:3x_scope` |
| 4倍镜 | `cbrg:4x_scope` |
| 6倍镜 | `cbrg:6x_scope` |
| 8倍镜 | `cbrg:8x_scope` |
| 15倍镜 | `cbrg:15x_scope` |

普通 AR、LMG 通常到6倍；M16A4、Mk47 Mutant 允许8/15倍是[官方20.1特例](https://pubg.com/en/news/1730)。DMR/SR通常到15倍；P90、Win94、VSS等固定镜与 UZI/Tommy/MP9、手枪、霰弹枪等有逐枪例外，不能仅按 TaCZ 的 rifle/sniper 分类判断。具体取值以完整图表和随模组打包的 `pubg_scope_policy.json` 为准，两者来自同一份生成结果。其他枪包的非CBRG瞄具保持原规则。

根据本次明确确认，**侧瞄按移除前的历史许可保留**。PUBG当前端游已在[37.1移除侧瞄](https://www.pubg.com/en/news/9002)，[41.1新增Hybrid Scope](https://pubg.com/en/news/9926)；本项目并不把旧侧瞄冒充当前Hybrid。历史侧瞄也有Groza、DP-28、MG3、Lynx等禁止项；弱证据与继承原包许可另行标注。TaCZ当前只有一个SCOPE槽，所以侧瞄作为单独瞄具使用，本次不提供同时装主镜与侧瞄的第二槽。

原有瞄具挂点保持原样；仅对原有瞄具槽、规则允许目标镜、但缺少模型挂点的枪使用已有通用后备。显示和ADS共用路径，位置是几何估算，未逐枪在游戏内验收。内置瞄具数据保留，外装与卸装按原生优先级处理。

切回初始或收紧规则不会删除枪上已有的配件NBT。原本无槽枪之前通过旧版本安装的镜会被原生读取隐藏，表示停止开放而不是自动销毁物品；对原本不兼容的旧装配应在切换前卸镜。此次不修改背包、枪包或存档实体。难度排名研究基于无配件参数，装镜后的ADS等变化不在原保序保证中。

## 每个物品独立配置

左侧为支持鼠标滚轮、滚动条的物品选择列表，右侧编辑当前物品的图标、名称、类型、真实资产 ID、数量范围和权重。新增时使用带预览的物品选择器，可搜索 ID、名称或分类；候选提示支持键盘与 Tab 补全。

唯一键为 `kind + id`：

| kind | id 表示什么 |
| --- | --- |
| `gun` | TaCZ 枪型资产 ID，例如 `tacz:ak47` |
| `ammo` | TaCZ 弹药资产 ID |
| `attachment` | TaCZ 配件资产 ID |
| `item` | 普通注册物品 ID |

同一物品不能重复添加；需要调整出现率或数量时编辑已有条目。没有 128 条物品的业务上限；文件大小、分块网络上传、单次生成实体数量仍有保护，不能把“目录无限制”理解为能一次创建任意多实体。

本存档的 `LootConfigStore` 在每次服务器运行首次初始化时，补入当前真实加载的全部有效 TaCZ 枪械、弹药、配件。新增枪械和配件默认权重 1，独立弹药默认权重 0；不自动纳入制造台、靶、枪箱等辅助物品，也不自动纳入所有原版物品。已有设置保留，安装新枪包不会把已经调好的权重恢复为默认值；补目录不是每次打开界面重复执行。

### 类别与枪类生成概率

主物品先抽类别，枪械类别接着抽枪类，再在选中的枪类内按逐枪有效权重抽取。其余物资类别直接按类内有效权重抽取。先执行当前实验开关的筛选、专用件降权，再把正有效权重条目分入以下10类。

| 类别 | JSON键 | 默认类别概率 |
| --- | --- | ---: |
| 枪械 | `gun` | 40% |
| 弹药 | `ammo` | 0% |
| 瞄具 | `scope` | 15% |
| 弹匣 | `magazine` | 15% |
| 枪口 | `muzzle` | 10% |
| 握把 | `grip` | 8% |
| 枪托 | `stock` | 5% |
| 激光 | `laser` | 2% |
| 其他配件 | `other_attachment` | 0% |
| 普通物品 | `item` | 5% |
| 合计 | | **100%** |

这是**项目建议的初始比例**，不是 PUBG 官方公布的绝对刷新比例。激光按语义单列：例如物理上占 GRIP 槽的 `cbrg:laser_sight` 仍进入激光池，不会混入握把池。未知语义配件进入其他配件池。

在顶部“基础设置”统一编辑类别百分比和物品基础权重；两者分别控制类别之间与同类物品之间的分配。类别区显示当前合计、每池可选数量和实际占比；所选物品显示所属池、池内占比、总体占比和有效权重。编辑中合计暂不等于100%仍可切页、保留草稿，但“保存全部”会拒绝未达到100%的配置。每项须为0～100%，服务端总和容差为 `1e-9`。

若实验筛选后某池没有正有效权重条目，该空池不参与抽样；它的概率按其余**原概率大于0的非空池**重新归一。类别概率为0的池始终关闭，不会因其他池为空而复活。所有正概率池都为空时，没有可选主物品，需调整类别比例或物品权重。表中比例是配置目标；存在空池时，应以界面显示的实际占比为准。

```text
类别实际概率 = 本类配置概率 / 所有正概率非空池的配置概率之和
池内物品概率 = 该物品有效权重 / 本池所有正有效权重之和
该物品总体概率 = 类别实际概率 × 池内物品概率
```

枪械细分为步枪、冲锋枪、机枪、霰弹枪、狙击枪、精确射手步枪、手枪、重武器和其他枪械。在基础设置展开“枪类概率”编辑九类百分比，合计100%；“按枪型数量恢复”使用完整已加载枪械目录中各枪类的数量占比。默认模式保留目录跟随能力，手动修改后保存为明确的九类概率。权重0仍计入目录数量；实际抽样将正概率空类的份额分配给其余正概率可选类。

```text
枪械总体概率 = 枪械物资类别实际概率 × 枪类实际概率 × 该枪在枪类内的权重占比
```

`general.gunSelection.probabilities` 缺省或为null表示按目录数量计算；手动配置完整填写 `rifle/smg/mg/shotgun/sniper/dmr/pistol/heavy/other` 九键。逐枪配弹使用既有独立设置。

例如瞄具类别实际占15%，池内两件物品权重为9和1，则它们在瞄具池内各占90%和10%，总体分别占13.5%和1.5%。增加枪型数量只改变枪械池内的分配，不再因枪型比配件多就自动抬高枪械类别的占比。

单品基础权重0表示不独立生成；类别概率0表示整类不独立生成。基础权重仍是相对权重，不是总体百分比。枪数量固定为1；其他物品的数量范围控制一次抽中后的实际数量。配套弹药和专用配件在主物品抽样之后额外产生，不占这10类的主抽样概率或面积密度名额。

官方刷新平衡只作为分类调配的参考：[PUBG 16.2](https://www.pubg.com/en/news/1717)曾将普通模式 Erangel 的弹匣刷新率下调约28%、瞄具上调约75%；[22.2](https://pubg.com/en/news/4555)将指定霰弹枪及对应弹药的刷新率在普通模式下调约30%、排位下调约20%。这些是相对原刷新率的变化，不能证明其内部采用本项目的两级抽样算法，不能推出绝对类别比例，也不能据此推断多数游戏都使用同一算法。

### 实验生成池与专用配件

界面保留可编辑的“基础权重”，同时显示“有效权重”、池内和总体抽取占比。实验规则先计算有效值，再交给上述类别抽样，不改写基础权重；切回初始即可恢复。基础权重已经是0的物品不会被实验或配套生成重新启用。

弹匣、瞄具、激光、子弹各自开启实验时，非上表所选ID的有效权重为0。配套弹药仍根据枪的实际弹种生成，不受独立弹药权重过滤影响。

枪口、枪托、握把按当前已加载枪械的原槽位、标签、安装锁和原生许可统计支持数：支持数为0者有效权重为0；支持数为正且不超过总枪数10%向下取整者为专用配件，权重取`min(基础权重, 0.01)`；其余保持基础权重。当前424枪对应阈值42，0.01是本类别池内的相对权重，并非固定1%总体概率。GRIP型激光按语义单列，不受握把实验误筛。

在`config → 基础设置`的通用生成参数中设置配套专用配件：

| 参数 | JSON字段 | 默认 | 范围 |
| --- | --- | --- | --- |
| 概率 a（界面填百分比） | `companionAttachmentChance` | 50%，JSON为0.5 | 0～100%，JSON为0～1 |
| 不同配件种类 b | `companionAttachmentKinds` | 2 | 0～16 |

每把成功生成的枪在配弹后抽签一次。抽中时，从该枪实际兼容、基础权重大于0且对应类别实验已开启的专用枪口／枪托／握把中，等概率无放回抽取最多b种不同ID，每种1件；不足b种时取全部。相同已装或内置配件不重复配发。a或b为0即关闭。

额外配件使用配弹半径及合法地面检查，不占主物品密度。位置不足、实体预算耗尽或单件构造失败时跳过该额外件，已成功提交的枪与子弹不回滚。区域日志分别统计主物品／弹药与附加配件。

## 先生成主物品，再给每把枪配弹

1. 按有效面积、区域系数、密度和平面约束产生本轮全部主物品。
2. 每把枪只从三个配弹方案中抽签一次，同时决定弹种和组数。三个默认方案均跟随自己的当前弹种，分别配1／2／3组。
3. 步枪、冲锋枪、机枪的方案概率默认30%／60%／10%；其他枪类默认60%／30%／10%。同枪各组使用抽中方案的同一个弹种。
4. 各份弹药在距对应枪 **1～1.5 格的水平环带**内随机摆放；最小、最大半径可在通用设置修改。
5. 每个生成物品，包括每一份配套弹药，都独立抽取连续的 `[0°, 360°)` 水平朝向；不是只选四个正方向。朝向与本轮随机种子固定，延迟加载不会重新抽签。

在“基础设置”选择枪后编辑三个配弹方案的弹种、组数和概率，并修改该枪每组发数；宽屏直接显示方案，窄屏由“配弹设置”进入。最后点击“保存全部”。三方案概率合计100%，支持0%；不允许负数、无效弹药或超过范围的数量。每组1～4096发，方案组数可在1～64修改，默认1／2／3。

| 枪械类别 | 默认每组发数 | 默认总数候选 | 默认方案概率 |
| --- | ---: | --- | --- |
| 步枪、冲锋枪、机枪 | 30 | 30／60／90 | 30%／60%／10% |
| 霰弹枪 | 10 | 10／20／30 | 60%／30%／10% |
| 狙击枪、DMR、手枪 | 15 | 15／30／45 | 60%／30%／10% |
| 火箭筒 | 1 | 1／2／3 | 60%／30%／10% |
| 榴弹发射器 | 3 | 3／6／9 | 60%／30%／10% |

默认分类由服务器目录提供，区分TaCZ同属rpg标签的火箭筒与榴弹发射器；DMR按项目已有枪类角色认定。配弹不再按弹匣容量计算。“跟随”在实际生成时读取已应用原生弹种：开启子弹实验时跟随合并结果，切回初始时跟随原弹种；显式ID不会自动重映射。此设置只控制地面配套物资，不修改枪本身可装填的弹种。

配套弹药不占面积密度计算的主物品名额，也不因为独立弹药权重 0 而停止产生。所有位置必须落在同一近似平面的已标记有效地板内；旋转后的模型占地、支撑、墙体碰撞和物品间重叠一并预检。没有足够合法空间时整块区域刷新失败并保留旧物资，`itemRespawn status` 报告原因；不会缩小环带、摆到未批准地板或静默丢弃配弹。

## 通用设置和区域系数

```text
λ = 有效区域面积 × 区域稀有系数 × lootDensity
目标主物品数 = floor(λ) + 一次概率为 frac(λ) 的额外一个
```

默认密度 0.1 件/㎡，即每 10㎡ 一个主物品。25㎡、系数 1 时先生成 2 个，再有 50% 概率多 1 个。多层区域面积逐格去重、各楼层累计，只按整个区域计算一次。

`general` 控制 `minItemsPerPlane`、`maxItemsPerPlane`、`planeSpawnChance`、`samePlaneYTolerance`、`minItemSpacing`、`lootDensity`、`ammoRadiusMin`、`ammoRadiusMax`。平面仍按已标记地板水平连通，且整个平面的最高、最低真实表面差不超过容差（默认 0.5 格）。

`maxItemsPerPlane=0` 禁止该平面产生主物品；`Integer.MAX_VALUE` 表示不再加小型固定上限，实际数量仍受地板、密度和间距约束。原来的 128 上限已废除。每个区域的刷新事务仍有 512 堆实体安全限制，包含自动配弹；超出时明确失败，不截断生成结果。

`config → 区域` 独立保存区域稀有系数，默认 1、0 禁刷。物品/通用设置与区域系数各自保存，返回父页面时草稿保留；实际刷新使用两边已经保存的值。

## 展示与拾取

物资载体为本附属的 `GroundLootEntity`，固定平放，不采用普通掉落物的浮动、转动、合并和自然消失。已保存概率列表的普通物品和方块（含权重 0）会自动同步掉落规则，和 TaCZ 三类战斗物品一样在真实落地后转为这种载体；玩家主动丢弃朝向为视角 ±15°。有效三维模型保留掉落地面变换大小，薄片和二维后备图标额外缩放 0.38，按真实可见网格贴地。详见[配置目录与模型对齐更新](配置物品掉落与模型对齐更新.md)。

准星指向有效物资时，高亮真实模型轮廓。默认主手空着按 **F** 拾取，可修改键位，副手可持物；处理本附属地面载体，包括自动生成物资和实际落地后的 TaCZ 枪械/弹药/配件转换品。空中及其他普通 `ItemEntity` 不走该路径，转换品也不会被下次刷新清理，详见[落地转换方案](TaCZ掉落物落地转换方案.md)。只有完成有效物资拾取时消费 F 的原版副手交换动作，其余情况保留原行为。旧潜行主手右键拾取仍可使用。背包只能装下一部分时余量留地面，服务端复核距离、朝向和墙体遮挡。
