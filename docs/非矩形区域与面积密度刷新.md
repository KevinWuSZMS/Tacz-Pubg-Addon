# 非矩形物资区域与面积密度刷新

Minecraft 1.21.1 / NeoForge 21.1.259 / TaCZ PUBG Addon，更新：2026-10-17。当前按独立物品生成，旧组合模板概念已取消；[本轮更新](物品生成与交互更新说明.md)。

## 真实形状与自动连接

编辑棒左键第一角、右键同层第二角，对空气右键保存，或使用 `/pubgdebug area add`。保存合格地板的逐格集合，多个矩形可以组成 L 形、十字形、孔洞或多层区域，外接矩形里的空白不会补上。白线只画临时选区外围，提交或擦除成功后立即消失；蓝覆盖表示保存的地板。

只合并已批准地板：

- 同一方块 Y，东、西、南、北水平共享边。
- X/Z 相同，方块 Y 相差 1～10 格，含第 10 格。
- 连接可传递；不同维度分别处理。

角点接触不算连接，不自动批准未标记楼层。对空气 Shift+右键或 `area remove` 只擦当前框内已保存地板，框外保留，删除桥接格可能使区域分裂。

## 编号、面积与系数

| 信息 | 含义 |
| --- | --- |
| 编号 | 全存档唯一正整数，递增分配，删除后不复用 |
| 维度与成员坐标 | 保存真实位置、孔洞和楼层 |
| 面积 | 去重地板数量，1 格计 1㎡，不同楼层累加 |
| 最小/最大坐标 | 仅作范围查看，不代替形状和面积 |
| 锚点 | 决定分裂后哪一部分保留原编号 |
| 稀有系数 | 默认 1，范围 0～1000，0 禁刷 |

合并保留最早编号和它的系数；分裂时含原锚点的一块保号，锚点已删除则按确定性坐标排序选一块，其余分配新号并继承系数。数据位于主世界 `data/tacz_pubg_spawn_areas.dat`。旧地板集合会迁移为有编号的区域，原坐标不变。

## 面积只决定主物品数量

```text
λ = 本轮有效面积 × 区域稀有系数 × 全局物资密度
目标主物品数 = floor(λ) + 一次概率为 frac(λ) 的额外一个
```

默认密度 0.1 件/㎡，每 10㎡ 一个主物品。25㎡、系数 1，目标为 2 个，另有 50% 概率多 1 个；50㎡、系数 2，目标为 10 个。系数或密度为 0 时禁刷，保底设置也不绕过。

本轮重新核验真实地板和净空，失效地板不计有效面积。整个持久区域计算一次总量，不能每层都重复使用整栋面积。各次主物品按配置中唯一 `kind + id` 的正权重选择；区域系数改变数量，不直接改物品之间的条件概率。

近似平面用于放置：水平连通且整体最高/最低实际表面差不超过配置容差，默认 0.5 格；保底、参与概率、主物品上限和间距由通用设置控制。当前不再有旧版 128 条物品或每平面 128 个的固定业务上限；实际摆放仍受空间限制。`maxItemsPerPlane=0` 禁刷，最大整数表示无额外小型上限。

全部主物品生成后，逐枪按基础弹匣容量计算 `ceil(容量/30)` 份对应弹药，每份 30 发，默认在枪水平半径 1～1.5 格的环带内随机放置，半径可调。每个主物品、每份配弹都有独立连续 `[0°,360°)` 随机朝向。**自动配弹不占主物品密度名额**；独立弹药权重默认 0，不影响配弹。

所有旋转后模型必须获得已标地板支撑、不穿墙、不相互重叠。每个区域的刷新事务仍有 512 堆实体安全限制，包括配弹。空间或安全限额不满足时整区域失败、旧物资保留，`itemRespawn status` 报告原因；不会截断配弹或偷偷跨出环带、未标区域。

## config 与刷新

1. `/pubgdebug config → 通用设置` 调密度、平面约束和配弹半径；主页面保存物品和通用草稿。
2. `区域` 页查看编号、维度、面积与范围，编辑稀有系数，单独保存。
3. 区域页预计主物品数使用父页面密度草稿预览；实际刷新使用两边已保存值。
4. `/pubgdebug itemRespawn` 固定配置、各区域形状/系数和随机种子，覆盖全存档所有维度已标记区域；未加载部分等待自然加载。

区域系数每批最多提交 1024 个修改，超过可先保存再继续。服务端检查权限、编号、范围和版本，合并分裂或多人同时编辑导致版本冲突时拒绝旧提交并保留草稿。

辅助查看：`/pubgdebug area list [页码]`、`area info <编号>`、`itemRespawn status`。

`area info <编号>` 可用 Tab 补全现有区域，候选提示包含维度、面积、稀有系数和坐标范围。地图编号命令与备份UUID也按各自已保存数据提供补全，详见对应说明。

## 逻辑树与代码

```text
矩形临时选区 → 人工核验 → 保存/擦除 → 清临时白线
  → 对已标地板求连通分量 → 继承编号/系数 → SavedData保存真实形状

config
  ├─ 唯一物品、权重、数量、密度、配弹半径 → 存档JSON，旧版先备份迁移
  └─ 区域稀有系数 → SavedData，独立版本与保存

itemRespawn
  → 固定配置、形状、系数、种子
  → 等待所需区块自然加载 → 核验地板 → 划分近似平面
  → 面积公式及概率取整 → 独立抽主物品及随机朝向
  → 逐枪配30发弹药及独立朝向 → 支撑/碰撞/空间事务预检
  → 成功才替换本区域原有本附属物资；失败保留并报告
```

`spawn/SpawnAreaSavedData` 和 `SpawnRegionTopology` 管形状及身份；`SpawnRegionConfigPayloads`、`SpawnRegionConfigScreen` 管区域编辑；`lootconfig/LootConfigModel`、`LootSpawnRules` 管物品和计数；`lootspawn/LootRespawnSavedData`、`LootSpawnPlacement` 管快照与摆放。编号属于具体存档，不动态注册进全局物品注册表，采用 NeoForge [SavedData](https://docs.neoforged.net/docs/1.21.1/datastorage/saveddata/)。

当前构建和检查结果见[更新说明](物品生成与交互更新说明.md)。历史区域实现日志 `logs/pubg-irregular-regions-build.log` 保留为当时证据，不代表新配弹与新交互已经实机测试。
