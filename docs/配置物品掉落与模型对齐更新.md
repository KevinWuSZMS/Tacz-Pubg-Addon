# 配置物品掉落接管、模型对齐与装配闪烁修复

日期：2026-10-18。目标：Minecraft 1.21.1 / NeoForge 21.1.259 / TaCZ NeoForge r7。

后续物理更新：按用户反馈，现已恢复“空中仍是 minecraft:item、落地才转换”和原 0.22×0.13 格小载体，允许模型边缘局部穿模；地面保留重力，移除支撑后继续下落。协议为 4，客户端取消额外交接等待和整模型方块扫描。两款激光配件的特效光束另已从实体外形剔除。详见[恢复小碰撞箱与抛出停顿修复](恢复小碰撞箱与抛出停顿修复.md)。下方模型对齐、目录、数量和 Z 补丁记录保留。

## 当前实现

最新尺寸规则：概率列表物品在抛出、落地及 `itemRespawn` 中均使用原生掉落物大小，取消本附属额外加入的 `0.38`、`0.6` 等缩小系数。保留作者原生 GROUND 变换；749 项占地资料已按此重算。见[尺寸更新](物资使用原生掉落物尺寸.md)。

进入世界后，所有已经保存到 `config → 物品概率` 的条目都适用固定朝向、落地转为固定地面物资的规则。**权重为 0 也生效**，普通物品和普通方块物品也包含在内；物品选择器中没有保存到概率列表的候选项不会仅因能搜索到就被接管。TaCZ 的枪械、散装弹药和配件仍通过其官方接口默认接管，辅助工作台、靶子等不会被默认目录自动加入；若人为显式添加为普通物品条目，则按该显式配置接管。

不用为每个物品注册一个新实体类型。统一的事件和渲染器只注册一次，世界配置建立不可变匹配集合；普通物品按注册 ID 判断，TaCZ 资产通过 `IGun` / `IAmmo` / `IAttachment` 判断。空中仍是 `minecraft:item`，真正落地后才转换为 **`tacz_pubg:ground_loot`**。转换后的物品继续支持高亮和空手 F 拾取，保留数量、全部物品组件、枪上配件、装弹状态、原拾取延迟与所有者限制，也不会被下一次 `itemRespawn` 误删。

## 配置目录的自动同步

新增 `DroppedLootCatalog`，服务端缓存与客户端缓存分别存放，单人集成服务器也不会共用一个可变集合。

| 时间点 | 行为 |
|---|---|
| 服务器完成启动 | 从本存档的已保存配置建立匹配集合 |
| 玩家登录 / 数据包同步 | 给对应玩家发送只含普通物品 ID 的快照，所有玩家均可接收，无需 OP |
| 保存配置成功 | 按新 revision 重建集合并广播给在线玩家 |
| 切换维度 | 重发同一存档的快照 |
| `/reload` 数据同步 | 再同步当前保存状态 |
| 退出服务器 | 清空客户端集合和未完成传输，避免串到另一存档 |

TaCZ 三类资产的接口匹配不需要重复传输数百个资产 ID；普通物品通过哈希集合匹配，不在每个实体 tick 或每帧扫描整个配置。同步按 6000 字符分块，完整合法快照才替换当前集合；错序、缺块、错误 ID、超时或超过既有 8 MiB 预算时保留上一完整集合。旧 revision 不能覆盖新 revision，退出后新存档可从 revision 0 开始。分块大小是传输预算，不是 128 个物品之类的业务数量上限。

配置草稿未保存时不改变运行规则。外部直接编辑 JSON 的重新读取仍遵循现有配置加载流程，不新增静默监视文件行为。

## 视角基础上的抛出朝向

玩家按 Q 丢弃或从背包向外拖出时，服务端监听 `ItemTossEvent`，只设置一次：

```text
itemYaw = normalize(playerViewYaw + random[-15°, +15°])
```

该事件在原版算完抛出速度、物品加入世界之前触发，所以不会改变原来的抛物线、力度或重力。不是每帧随机，也不会在落地时再随机。落地载体保留相同 yaw，客户端衔接仍使用最后可见的角度与生成包角度量化规则。

对于其他代码生成且能找到玩家 thrower 的新掉落物，加入世界时补一次朝向；这里只处理角度，不在区块尚未 FULL 时读取地形。已经从磁盘加载的掉落物不重新随机，没有可识别玩家来源的物品保留其原朝向。

## 悬空与碰撞载体偏移

这次问题主要发生在本附属的测量/绘制适配层，不需要改写枪包原文件。

- TaCZ 为没有 UV 的面提交零面积占位顶点；旧测量把这些骨骼原点误算成真实枪身边界。
- 旧测量包含一些隐藏部件，但真正绘制又按另一套规则隐藏它们，计算出的最低点与可见模型不一致。
- 旧地面绘制调用共享可变枪械模型的完整渲染路径，影响手持和装配界面使用的模型缓存。

现在只读作者静态姿态，测量与绘制共用同一套当前物品显隐和实际配件组合，测量剔除零面积面，按真实可见网格居中并贴地。不会改变模型比例来掩盖偏移。

离线核查 **424 把枪、78 种弹药、247 个配件，共 749 个唯一 ID**。旧放置有 309 项最低点偏差，其中枪械 278、弹药 3、配件 28；包括微小偏差，并非声称全部曾在游戏画面中明显悬空。M7 `classicr:ngsw_r_renewed` 的旧可见枪身悬空约 **0.1844604 格**；Division 的 36 把枪中 30 把存在同类偏差。新可绘制网格最低点均归零，再加统一 0.002 格抬升。

F3+B 显示的仍是实体载体碰撞箱，不代表长枪每个部位都有刚体碰撞；本次修复的是可见模型和实体落点的相对位置。客户端选择用实际完整模型边界，服务端占地表按默认/内置配件生成，不声称每一种安装配件组合都已有单独服务端模板。详细逐项结果见[模型对齐说明](TaCZ地面模型对齐修复.md)与[749 项审计](../logs/ground-loot-model-alignment-audit.json)。

## Z 装配闪烁

目前能够证实并已修复的有两条路径：

1. **本附属问题**：地面枪械绘制会修改第一人称共用的模型缓存。现已移除地面路径对完整 `model.render()` 和动画清理函数的调用，采用只读静态网格，隔离这条污染路径。
2. **TaCZ 原渲染器问题**：合法的帧插值 `partialTicks=0` 在跳跃晃动中可产生 `0/0 → NaN`，随后使骨骼变换无效。新增客户端补丁跳过无效采样，并对装配打开进度作有限值和 `[0,1]` 边界保护；正常动画、ADS 和服务器枪械参数保留。

仅按 Z 的原路径只打开界面，不发送装配包或重启切枪动画。当前 Z 与 Xaero 放大小地图有键位冲突，但没有证据把双闪确定归因给它，本次未改用户键位。

**上述修复已实现，但没有实测证明“两次闪烁”已完全消失或只有一个原因。** 详见[静态调查与补丁](TaCZ装配闪烁静态调查.md)。
