# TaCZ 地面模型对齐修复

本次修复在 `tacz_pubg` 的适配层完成，不改写原枪包、来源 HMCL 安装或任何存档。这里记录的是离线源码与模型几何核查，不是启动游戏后的视觉验收。

后续更新：两款激光配件光束已从静态网格及外形计算剔除。实体碰撞按用户反馈恢复原 0.22×0.13 格小载体，允许模型边缘局部穿模；地面重力保留，抛出时改回原版运动、落地后转换。当前实现及验证见[小碰撞箱与停顿修复](恢复小碰撞箱与抛出停顿修复.md)。本文的完整模型测量与贴地处理仍用于显示和选取，不扩大物理碰撞。

## 确认的原因

旧流程的“计算模型边界”和“真正画模型”不是同一个几何集合。

1. TaCZ r7 的 `BedrockCubePerFace` 给未设置 UV 的面创建四个 `(0,0,0)` 顶点。这个面面积为零，屏幕上没有可见图形，但旧边界计算器把它所在骨骼的原点也算作枪械的一部分。作者将骨骼旋转中心放在模型外属于正常建模方式，这种不可见占位点就会错误地扩大边界。
2. 旧测量跳过了部分手臂和弹匣，但未按当前枪械判断瞄具导轨、折叠机械瞄具、战术护木、转接件等。真正的 TaCZ 渲染回调又会隐藏它们，导致用不可见部件确定地面高度。
3. 地面渲染调用共享 `BedrockGunModel.render()`，该调用写入当前枪物品、配件缓存、导轨状态等，并执行功能渲染回调。旧骨骼快照没有恢复全部内部缓存。第一人称、改装界面和地面枪可能共用此模型，不能让地面绘制改变它们的状态。

可复核的典型例子：

| 模型 | 旧流程下可见模型距地面的离线偏差 | 修复后几何最低点 |
|---|---:|---:|
| `classicr:ngsw_r_renewed`（M7 Battle Rifle） | 约 0.18446 格 | 0，再加统一 0.002 格防闪烁抬升 |
| `gz:black_market_rpk74` | 约 0.55651 格 | 同上 |
| `gz:t81lmg` | 约 0.20362 格，且旧边界误判平放轴 | 同上 |

上述数值由实际作者网格、TaCZ 原始坐标变换、缺失面的占位点及默认内置配件计算得到；不表示截图中的每把枪都已在游戏里实测。

## 实施的流程

1. 按当前 `ItemStack` 取得枪械和内置／已安装配件、基础／扩容弹匣、枪膛及余弹状态。
2. 用 TaCZ r7 的同名骨骼显隐规则选择真实物理部件。手臂、额外换弹弹匣、枪口火焰、激光光束、镜内遮罩及分划线不计入物品外形；外部瞄具镜身、镜圈、实际配件和当前弹匣保留。
3. 只读取作者的原始平移与初始旋转。地面路径不再调用共享动画清理、模型功能渲染或模板缓冲操作，因此不修改手持／改装模型。
4. 计算边界时，每四个顶点作为一个面，剔除没有面积的退化面。一个有效的二维平面仍然有面积，因此不会把正常薄片、图标状配件一并丢掉。
5. 边界测量和绘制使用完全相同的网格遍历与显隐策略。已有配件也在其实际安装节点合成并纳入测量。
6. 以实际可见网格的中心居中，以最薄方向平放，并令最低点贴到实体原点所在的地面；保留原作者的掉落物尺度，真正的薄层仍使用既有 ×0.38 规则。
7. 飞行掉落物和 `tacz_pubg:ground_loot` 继续共用这套绘制流程。落地切换不再因为两套模型偏移而跳动。

## 对应文件

- `GroundGunModelRenderer`：按物品状态组合枪体及实际配件，共用测量与绘制遍历；不再调用 TaCZ 共享可变模型的功能渲染方法。
- `GroundSupplementModelRenderer`：弹药及单独配件使用同样的只读静态姿态和真实面测量。
- `GroundLootBonePolicy`：可独立验证的 TaCZ 骨骼显隐规则。
- `GroundLootMeshBounds` / `GroundLootQuadGeometry`：四顶点面测量与退化面判断。
- `scripts/generate-ground-loot-footprints.py`：只读已安装资源，生成服务器可用的数值占地及逐项审计。
- `assets/tacz_pubg/ground_loot_footprints.json`：服务器数值资源，无客户端模型或 GPU 依赖。

客户端光标选择使用当前完整模型的实时边界，包括实际安装配件；服务器数值占地按已安装枪包的默认／内置配件姿态生成，不意味着每一种外部配件组合都有单独的服务器数值模板。

## 验证与界限

独立 Java 几何／显隐检查共 64 项通过，覆盖远处骨骼原点产生的零面积假面、真实薄片、有效三角形、非有限输入、基础及扩容弹匣、导轨、护木、枪膛余弹、配件转接件和瞄具内外部件。

完整资产逐项结果见 `logs/ground-loot-model-alignment-audit.json`，包含全部 424 把可用枪、78 种弹药、247 个配件的分类及旧／新边界。无模型或完全没有物理网格的物品明确回退为水平图标，不编造模型。已知源资源缺失会单独列在 `errors`，不静默修改枪包。

最终共有 749 个唯一 ID：424 把枪均使用 3D；弹药为 46 个 3D、32 个图标；配件为 211 个 3D、36 个图标。旧放置存在最低点偏差的共有 309 项：278 把枪、3 种弹药、28 个配件；其中 306 项存在悬浮，3 项存在部分穿入。这个统计包括细小的离线几何偏差，不等同于 309 个都已在画面中报告的故障。新流程的所有可绘制网格最低点均为零，再统一加 0.002 格抬升。

Division 枪包的 `gz` 命名空间共核查 36 把，30 把存在旧偏差。此前肉眼不明显的弹药偏差包括 `cib:80`、`tacz:357mag`、`tacz:45acp`，也已纳入同一修复。唯一缺失的既有源模型是 `classicr:muzzle_silencer_default` 引用的 `assets/classicr/geo_models/attachment/muzzle_silencer_default_geo.json`，它使用安全的水平图标回退；这里没有为它假造来源模型。

本轮没有启动 Minecraft、服务器、世界或光影。最终构建与其余掉落行为、改装界面修复的统一验证由主任务执行。
