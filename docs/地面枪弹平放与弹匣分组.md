# 地面物品平放、配套弹药与拾取

Minecraft 1.21.1 / NeoForge 21.1.259 / TaCZ NeoForge r7 / `tacz_pubg`。更新：2026-10-19。保留旧文件名以兼容链接；当前规则已改为独立物品生成，旧版按弹匣拆堆说明不再适用。配置见[物品配置与全存档刷新](枪组配置与全图刷新.md)，抛出到落地的最新行为见[小碰撞箱与停顿修复](恢复小碰撞箱与抛出停顿修复.md)：空中保留原版运动，真实落地后转换，地面小箱保留重力、支撑移除后继续下落，拾取仅限已落地物资。

## 三维模型大小与平放

枪械、弹药、配件有真实三维模型时，重建其完整 `ItemDisplayContext.GROUND` 变换，保留普通掉落物的模型大小，取消此前对所有模型额外乘 0.38 的缩小。GROUND 是显示变换，不等于平放，所以还需要测量实际网格边界。

处理顺序为：读取作者原始静态姿态和当前物品的装弹/配件状态，使用同一显隐策略测量和绘制实际网格，剔除缺失 UV 面产生的零面积假顶点；经过 GROUND 变换后把最薄轴转向竖直，使 X/Z 居中、可见最低点贴地，再抬高约 0.002 格减少闪烁。地面路径不再修改共享枪械动画或调用完整功能渲染。手臂、枪口火焰和镜内遮罩等不参与物品外形；实际安装配件纳入。详见[749 项模型对齐修复](TaCZ地面模型对齐修复.md)。

按最新要求，概率列表中的全部物品抛出与落地都使用原生掉落物大小。薄片、普通二维物品、TaCZ 后备图标也不再额外乘 `0.38`、`0.6` 等系数；保留模型作者自身的原生 GROUND 变换（例如原生附件图标的 `0.5`），它不是本附属追加的缩小。`itemRespawn` 共用相同渲染，尺寸与手动丢弃保持一致。仍按真实尺寸测量贴地、轮廓、准星选择和生成占地，运动碰撞箱不扩大。

全部生成物品，包括每份配弹，都有独立的连续 `[0°, 360°)` 水平随机朝向，保存后保持静止。地面实体不浮动、不持续自转、不自动合堆或自然消失。

客户端缓存测量边界，资源重载时清空。服务端使用由枪包生成的数值占地清单，为初始生成模型做已标地板支撑、墙体碰撞和重叠检查；它不是以客户端报告的尺寸决定合法位置。加装或修改枪包后，需运行 `scripts/generate-ground-loot-footprints.py` 并重新构建，更新默认生成占地。生成占地、模型可见性和准星边界均独立于运动使用的 0.22×0.13 格小碰撞箱；装配包围脚本及资源作为上一轮研究保留，运行时不再使用。特殊动画、动态骨骼和未被清单覆盖的自定义资源仍须按实际模型适配。

## 新配弹规则

先生成全部独立主物品，再遍历其中的每把枪：

```text
方案 = 从逐枪三个配弹方案抽一次
默认方案 = 自身弹药×1组／自身弹药×2组／自身弹药×3组
总发数 = 组数 × 该枪每组发数
```

在 `config → 物品概率` 选择枪后点击“配弹设置”，修改三个方案的弹种、组数和概率，以及该枪每组发数，再返回“保存全部”。只有一次抽签，同枪各组弹种一致。三个方案默认均跟随当前生效的枪械弹种，也可指定其他已加载弹种；只改变地面配套物资，不改变枪的装填兼容。默认各组在枪水平半径1～1.5格内出现，半径可在通用设置调整；每组有独立随机朝向。

| 枪械类别 | 默认每组发数 | 总发数候选 |
| --- | ---: | --- |
| 步枪、冲锋枪、机枪 | 30 | 30／60／90 |
| 霰弹枪 | 10 | 10／20／30 |
| 狙击枪、DMR、手枪 | 15 | 15／30／45 |
| 火箭筒 | 1 | 1／2／3 |
| 榴弹发射器 | 3 | 3／6／9 |

步枪、冲锋枪、机枪的三个方案默认概率为30%／60%／10%，其他枪类为60%／30%／10%。三方案概率必须合计100%。当前规则替换按基础弹容向上取整的旧规则；独立弹药默认权重0，配套弹药仍按逐枪设置生成，不占主物品密度。“跟随”支持实验弹药切换，显式ID保持不变。旧配置先备份，再自动采用新默认值。

配弹位置必须仍是同一近似平面内的已批准地板，并允许整个旋转后模型得到支撑。放不下、穿墙或达到实体安全上限时，整区域刷新失败、旧物资保留，`itemRespawn status` 给出原因；不会把弹药移出设定环带、跨到未标记地板或静默少生成。

## 准星选择与 F 拾取

客户端采用真实平放模型边界，反向变换当前水平角度后进行射线与有向包围盒（OBB）求交。比包围球更贴合细长枪械，减少准星落在枪旁空白处却选中的情况；先用方块碰撞限制射线长度，再选最近的有效物资，避免隔墙选中。选中时高亮实际模型轮廓。

默认主手空着按 **F** 拾取，副手允许持物，可在键位绑定修改。只处理本附属的 `GroundLootEntity`。TaCZ 枪械/弹药/配件，以及已保存概率列表中的普通物品和方块（含权重 0），抛出时固定朝向，实际落地后转为这种载体，此后也参与选择、高亮和 F 拾取；主动丢弃朝向为视角 ±15°。空中与目录外其他掉落物不走 F 路径。只有存在有效拾取操作时消费 F 的原版副手交换动作，其余情况保留原行为。原来的潜行＋主手右键拾取入口继续保留。

服务端再次检查实体类型和来源、主手空、原版实体交互距离（生存通常 3 格，取本实现允许的上限）、朝向、OBB 和方块遮挡，再把真实物品放入背包。客户端选中只是提示，不直接决定给物品。

## 数量与存档

`GroundLootEntity` 分开同步基础 `ITEM` 和实际 `QUANTITY`，拾取时按物品及背包的合法堆叠上限转移。背包不够时只减去真正装入的数量，余量留地面；满背包不会吞物资。

加载已有实体不会擅自重写数量。要采用新的独立物品和配弹规则，保存 config 后明确执行：

```mcfunction
/pubgdebug itemRespawn
/pubgdebug itemRespawn status
```

该命令覆盖全存档所有维度的已标区域，未加载部分延后处理。

实现集中在 `lootspawn/client/GroundLootRenderer`、`GroundGunModelRenderer`、通用 TaCZ 模型渲染、选择与拾取相关类，以及服务器的 `LootSpawnPlacement` 和模型占地清单。本轮构建与逻辑检查见[更新说明](物品生成与交互更新说明.md)；没有启动 Minecraft 验证全部自定义模型或全部光影实际画面。
