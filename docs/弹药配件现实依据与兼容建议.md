# 弹药、瞄具与其他配件：现实依据和游戏兼容建议

调查日期：2026-10-18，Asia/Shanghai。目标环境：Minecraft 1.21.1 / NeoForge / TaCZ 1.1.8-hotfix-r7。PUBG 对照范围限定为**端游普通与排位**，不引入手游或特殊玩法规则。

本文件给出分类依据和统一建议；完整本地对应表见[弹药配件兼容性总览](弹药配件兼容性总览.md)。本次只读检查了 `run/tacz/` 中默认包目录及八个 ZIP 的索引、语言、枪械数据和配件数据，没有改枪包、删除注册项或启动 Minecraft。这里的现实资料用于识别名称、平台和游戏抽象，不提供现实武器改装步骤或装药参数。

## 先区分三个问题

“名称相近”“能被同一把游戏枪接受”“现实中确实适配”是三个不同结论。建议每条记录分开保存：原始 `kind + id`、当前显示名、现实口径/接口族、PUBG 玩法类别、游戏兼容目标、证据和待核验项。名字可以统一展示，旧 ID 应继续注册，存档和其他附属引用不因整合失效。

例如 `cbrg:ammo_762` 可以是 PUBG 的统一 7.62mm 补给类别，同时明确注明它是玩法抽象；不能因此把现实的 7.62×39、7.62×51 和 7.62×54R 写成同一种枪弹。

## 当前安装包的关键发现

下表结论来自本地文件内容，不是按文件名推测现实型号。资源位置均相对于各枪包根目录；ZIP 内目录与解压目录采用同一结构。

| 本地证据 | 可以确定的内容 | 整合时的处理建议 |
| --- | --- | --- |
| `data/tacz/data/guns/ak47_data.json`、`sks_tactical_data.json`；`data/suffuse/data/guns/svd_data.json` | 当前 `ammo` 都引用 `cbrg:ammo_762`，已经采用 PUBG 的 7.62mm 抽象 | 保留其 PUBG 类别；需要现实配置时另写逐枪覆写，不能由这个 ID 反推真实口径 |
| `data/ccrp/data/guns/ak47_spent_bullet_data.json` | 仍引用 `tacz:762x39` | 与上面的 PUBG 类别分层记录，避免仅显示“7.62”造成误判 |
| `data/classicr/data/guns/m24_renewed_data.json`；`data/cib/data/guns/svd_data.json` | 分别引用 `tacz:308` 和 `tacz:762x54` | 这说明相似枪名在不同包里可能遵循不同弹药规则 |
| `data/tacz/index/ammo/338.json` | 注册 ID 是 `tacz:338`，但当前 `name` 指向 `cbrg.ammo.ammo_300m.name`，显示为 `.300 Magnum` | **不能自动归入 .338 Lapua 家族**；保留原 ID，记录当前覆写，并由最终玩法表明确其用途 |
| `assets/tacz/lang/en_us.json` 的旧 `tacz.ammo.338.name` | 旧语言键仍写 `.338 Lapua Bullet`，但当前索引已经不用这个键 | 旧语言文本不是当前注册对象语义的充分依据 |
| `hamster:compact_ammo`、`hamster:medium_ammo`、`hamster:long_ammo` | 显示名是 Short / Medium / Long Bullet，信息不足以确认完整现实口径 | 保留独立身份、标注待核验，不批量并入 9mm、5.56 或 7.62 |
| `tacz:ammo_mod_fmj`、`ammo_mod_he`、`ammo_mod_hp`、`ammo_mod_i`、`ammo_mod_slug` | 使用 `extended_mag` 槽，实际数据包含伤害、穿透等效果 | 不因为槽位叫弹匣就把它们归为扩容弹匣 |
| `cbrg:laser_sight`；`ccrp:weapon_m203` | 都使用 `grip` 槽，前者是激光效果，后者带下挂武器配置 | `grip` 是游戏插槽，不等于所有条目现实中都是握把 |
| `ccrp:stock_192_gasknob` | 使用 `stock` 槽，数据包含射速和后坐力修改 | 不能只凭插槽把它当成普通枪托并全平台放通 |

原包的 `hidden` 标记也应保留。例如 `cib:g3s` 被标记为隐藏；这不等于它应被删除或自动加入公共物资池。

## 弹药的现实分类与游戏近似

建议先建立完整口径族，再单独声明 PUBG 别名。表里的“可统一”均指**模组玩法设计**，不是现实中无条件互换的声明。

SAAMI 在 2026-10-12 新接受 `5.56 COMMERCIAL` 标准时，仍明确说明符合该商业标准不等于符合军用或 NATO 标准，不能据名称近似作笼统互换声明。因此这里把 .223 / 5.56 合成游戏 family 时，应保存原始名称和标准身份。[SAAMI 5.56 COMMERCIAL 官方公告](https://saami.org/saami-announces-acceptance-of-a-new-cartridge-556comm/)

| 口径或类别 | 现实依据与边界 | 本地 ID 示例与建议 |
| --- | --- | --- |
| 5.56×45 与 .223 Remington | 名称和外形近似，但军民标准、适用条件有差异，不能声明双向无条件通用。[SAAMI FAQ](https://saami.org/faqs/) | `tacz:556x45`、`ccrp:556x45_m855`、`ccrp:556x45_m995` 与 `cbrg:ammo_556` 可在简化玩法中归入 5.56 补给池；M855/M995 的弹种身份另存 |
| 7.62×51 与 .308 Winchester | 可作为游戏里的近似家族；现实军民标准不同，不能只因尺寸近似推导所有枪都兼容。[SAAMI 军民弹药互换说明](https://saami.org/wp-content/uploads/2024/11/SAAMI-Generally-Accepted-Firearms-and-Ammunition-Interchangeability-10-8-2021.pdf) | `tacz:308` 可以作为已核验 .308 类条目的游戏代表；不要把所有 `762` 前缀直接收进来 |
| 7.62×39 与 7.62×54R | 是不同的完整弹种，不能仅因“7.62”数字相同而宣称现实通用。制造商分别列为不同产品。[PPU 7.62×39](https://ppu-usa.com/ppu/7-62x39/)、[PPU 7.62×54R](https://ppu-usa.com/ppu/7-62x54-r/) | `tacz:762x39`、`tacz:762x39copper` 属于需要核验的 ×39 候选；`tacz:762x54`、`tacz:762x54r` 是 ×54R 候选，省略 R 的本地命名仍需核对。可另将特定 PUBG 枪加入 `cbrg:ammo_762` 抽象，保留其现实注释 |
| 9×19、.45 ACP、10mm Auto | 不能按“手枪/冲锋枪弹”合并。厂商明确区分 9×19、4.6×30、300 BLK 等类别，也分别提供 .45 ACP 和 10mm 平台。[HK 官方口径比较](https://www.heckler-koch.com/Downloads/Produktinformationen/EN/HK437%20Handbook%20EN.pdf)、[FN 官方 .45 ACP / 10mm 产品说明](https://fnamerica.com/press-releases/fn-unveils-the-fn-510-tactical-and-fn-545-tactical/) | `tacz:9mm` / `cbrg:ammo_9mm`、`tacz:45acp` / `cbrg:ammo_45acp`、`tacz:10mm` 分族；`9mm` 简写本身不足以证明某个未知模型就是 9×19 |
| 12 Gauge | `Gauge` 是霰弹枪口径类别，不能当作 12mm。完整现实识别还涉及壳长和弹种；游戏可以只保留一个 12 Gauge 补给池。[SAAMI 霰弹标准](https://saami.org/wp-content/uploads/2022/08/ANSI-SAAMI-Z299.2-Shotshell-2019-Approved-2019-04-23.pdf) | `tacz:12g` / `cbrg:ammo_12g` 可统一 12 Gauge 玩法类别；`tacz:410_bore`、`cib:18.4`、`suffuse:23mm` 不因外观是霰弹就一起并入 |
| .300 AAC Blackout | 是独立的标准弹种；简称 `.300` 不能与 .300 Winchester Magnum 混同。[SAAMI 标准中的 300 AAC Blackout](https://saami.org/wp-content/uploads/2026/02/SAAMI-Z299.4-CFR-2025-Centerfire-Rifle-Approved-2-10-2025-2026-02-13.pdf) | `tacz:300blk` 独立；不能把当前显示 `.300 Magnum` 的 `tacz:338` 变成它的别名 |
| .338 Lapua Magnum 与 .300 Winchester Magnum | 是两个不同家族，也不能把 .338 Lapua 与 .338 Norma 混同。[Lapua .338 LM](https://www.lapua.com/cartridges/338-lapua-magnum/)、[Lapua .300 Win Mag](https://www.lapua.com/cartridges/300-winchester-magnum/)、[Lapua .338 Norma](https://www.lapua.com/cases/338-norma-magnum/) | 当前 `tacz:338` 存在上表显示覆写，先标记其游戏角色；现实 .338 LM 分类必须有额外证据 |
| .50 BMG / 12.7×99 | .50 BMG 对应 12.7×99，不能只因“12.7”把不同长度的弹种合并。[Barrett 官方规格](https://barrett.net/wp-content/uploads/2023/10/M107A1_16693_OP-Manual_8.5X5.5_C-For-Website.pdf) | `tacz:50bmg` 独立；`cib:127x108`、`suffuse:12.7x108mm`、`suffuse:12.7x55` 分开，`.50 AE` 的 `tacz:50ae` 也不是 .50 BMG |
| 5.7×28 | FN 为 P90 / Five-seveN 体系开发的独立口径，后来完成 NATO 标准化；不属于泛称 5.56。[FN 历史与标准化说明](https://fnherstal.com/en/5-7x28mm/) | `tacz:57x28` / `cbrg:ammo_57mm` 可核验为同玩法家族；不要并入 `cbrg:ammo_556` |
| 4.6×30 | HK 明确列为 MP7 的口径，与 5.7×28、9×19 分开。[HK MP7 官方资料](https://www.heckler-koch.com/en/Products/Military%20and%20Law%20Enforcement/Submachine%20guns/MP7) | `tacz:46x30` 保留独立；是否进入 PUBG 初始物资池，应由端游对应枪表决定，不能因同属 PDW 就统一到 5.7 |

5.45×39、5.8×42、9×39、7.62×25、.22 LR / .22 WMR 等也应各自保留完整口径族。`tacz:762x25` 不能仅因 7.62 前缀进入步枪补给池，`cib:9x39mm` 不能仅因 9mm 前缀进入 9×19 池。没有充分型号证据的条目先保持独立，不能用自动字符串截断替代判断。

## PUBG 规则要单独记录版本

PUBG 的供弹设计本身会刻意偏离现实，也会随版本改变。官方 30.1 公告将地图自然刷新的 SMG 弹药统一为 9mm，并明确 Tommy Gun 从 .45 ACP 改为 9mm、UMP45 改名为 UMP 并改用 9mm。因此，做当前端游玩法时不能沿用旧印象，把这些枪的补给继续固定为 .45 ACP。[PUBG 30.1 官方公告](https://www.pubg.com/en-asia/news/7424)

P90 是需要单列的例外。官方 13.2 的初始设计就是专用 5.7mm 补给，并带固定不可拆的瞄具、消音器等；后续 32.1 仍单独调整 5.7mm 弹药重量。这些公告可支持独立供弹与内置配件的设计方向，不能用来保证本地替代模型已经完整实现这些功能。[PUBG 13.2](https://www.pubg.com/en-asia/news/1369)、[PUBG 32.1](https://pubg.com/en-asia/news/7810)

建议在对应表中同时保存 `real_caliber_family` 与 `pubg_supply_family`。端游模式可使用 `cbrg:ammo_556`、`cbrg:ammo_762` 等统一补给；现实分类仍保留 ×39、×51、×54R 的区别。额外枪包中没有端游对应物的枪不因装进工作区就自动改成 PUBG 口径。

## 瞄具：公共导轨与专用平台

现实中的瞄具通用性主要来自**安装接口和匹配的底座**，不是“都叫 4 倍镜”或“都是步枪”。Aimpoint Micro T-2 的一个具体产品版本明确带 Weaver / Picatinny 标准底座，其他版本则有不同底座；不能由镜体同名推导所有版本接口相同。[Aimpoint 官方产品资料](https://www.aimpoint.com/products/micro-t-2-2-moa-red-dot-reflex-sight-with-standard-mount-for-weaver-picatinny/)

本地 `cbrg:red_dot`、`cbrg:holographic_sight`、`cbrg:2x_scope` 至 `15x_scope` 可以定义为游戏里的公共瞄具族，但只放通已经具备对应显示节点和兼容声明的枪；倍率是玩法属性，不是接口证据。`cib:g3s`、`cib:qmk191`、`tacz:scope_qmk152` 等带平台特征的条目先按专用候选保留，未确认模型底座和枪包白名单前，不全局映射成公共镜。

FN 官方还区分 P90 Standard 的内置光学瞄具和 P90 Tactical 的上方 Picatinny 导轨。同一个枪名可能对应不同实际结构，因此本地 `tacz:p90`、`origin:p90` 等要看真实模型和内置配置，再决定是锁定内置镜，还是允许公共镜；不能只看 `p90` 字样。[FN P90 官方型号说明](https://fnherstal.com/en/defence/portable-weapons/fn-p90/)

建议给每把游戏枪记录 `optic_platform`、`has_builtin_optic`、可换瞄具清单和显示节点可用性。自动规则只补已证实的公共平台，不覆盖专用镜或内置镜；未核验关系在界面中显示“待核验”，不要伪装成已确定的现实适配。

## 弹匣：平台与三种效果分开

现实弹匣并不按“所有 5.56 共用一个”划分。Magpul 的 AR/M4 弹匣资料列出具体兼容平台，而官方目录还分别提供 AK/AKM、AK74、HK G36、Steyr AUG 等弹匣；相同口径不能证明弹匣接口相同。[Magpul AR/M4 官方资料](https://magpul.com/media/wysiwyg/GIS/MAG557_PMAG_30_AR_M4_GEN_M3_GIS_01.pdf)、[Magpul 官方平台目录](https://magpul.com/instructions)

PUBG 则将弹匣抽象为三种**效果**：快速换弹、扩容、快速扩容。官方 15.1 用 M416 举例，扩容弹匣容量可以高于快速扩容，后者用部分容量换取换弹速度；“第三档”不是容量必然最多。这里引用的是该版本的历史设计依据，不将旧数值直接当成 2026 年所有枪的现行数值。[PUBG 15.1 官方公告](https://www.pubg.com/en-asia/news/1358)

当前本地 CBRG 也使用这个编码：

| 效果 | 步枪 ID | 手枪 ID | 狙击枪 ID | 数据中的级别 |
| --- | --- | --- | --- | --- |
| 快速换弹 | `cbrg:quickdraw_mag_rifle` | `tacz:light_extended_mag_1` | `tacz:sniper_extended_mag_1` | 1 |
| 扩容 | `cbrg:extended_mag_rifle` | `tacz:light_extended_mag_2` | `tacz:sniper_extended_mag_2` | 2 |
| 快速扩容 | `cbrg:extended_quickdraw_mag_rifle` | `tacz:light_extended_mag_3` | `tacz:sniper_extended_mag_3` | 3 |

三个步枪配件的本地数据分别设 `extended_mag_level` 为 1、2、3；当前 `tacz:ak47` 的对应容量数组是 `[30,42,40]`，正好说明不能把数组解释为“依次变大”。统一时应分开 `weapon_bucket` 和 `effect_kind`，并保留逐枪的容量、换弹与模型可用性；不得把 `extended_mag_level = 3` 的 `tacz:ammo_mod_fmj` 当成快速扩容弹匣。

为了方便端游玩法，可以统一同一武器类别的抽象弹匣物品，在安装到不同枪后显示该枪自己的弹匣模型。需要标注这是玩法简化，不能写成现实 AR、AK、AUG 弹匣互换。固定供弹、内置弹仓、弹链或本身不支持换装的枪，应有独立例外；不能只看其枪种就自动增加弹匣槽。

## 枪口、握把与枪托不能只看插槽

| 类别 | 现实支持 | 本地统一建议 |
| --- | --- | --- |
| 枪口装置 | 还要匹配口径范围和安装接口。SureFire 对一个具体消音器明确列出适用口径与自家 Fast-Attach 配套接口，不是所有“步枪消音器”都同型。[SureFire 官方资料](https://www.surefire.com/socom556-rc2/) | `cbrg:suppressor_rifle`、`suppressor_sr`、`suppressor_pistol` 可作 PUBG 类别；`tacz:muzzle_silencer_ursus` 等未知现实对应型号只赋游戏类别，保留原白名单和模型检查 |
| 握把/下挂 | Picatinny 与 M-LOK 是不同接口概念。Magpul 专门提供 RVG 的 M-LOK 转接产品，并说明其兼容范围，并非所有附件任意互换。[Magpul RVG 接口说明](https://magpul.com/rvg-m-lok-adapter-rail.html?mp_global_color=118) | `cbrg:vertical_foregrip`、`angled_foregrip`、`halfgrip` 等可做公共玩法效果；`ccrp:weapon_m203` 是下挂武器候选，`cbrg:laser_sight` 是激光功能，不能和握把无差别归一 |
| 枪托/贴腮板 | 厂商按 AR、AK、专用底盘等平台分别列出枪托产品；不同平台的同名“枪托”不自动通用。[Magpul 枪托平台目录](https://magpul.com/firearms-accessories/stocks.html) | `cbrg:cheek_pad` 与普通枪托分开；`ccrp:stock_b5_precision_stock`、`stock_cqr_gen1` 先保留平台候选。当前占 `stock` 槽但实际是其他功能的条目，不被批量放通 |

游戏里仍可保留同一槽位互斥的便利规则，例如激光和握把争用一个下挂槽；应说明这是 TaCZ/本枪包的插槽设计，不是现实接口结论。角色动画、定位骨骼、枪体空间和配件显示也必须匹配；修改兼容白名单本身不证明模型已经不穿模。

## 建议的统一流程

1. 冻结当前全部原 ID、索引引用、显示名、隐藏标记和原始兼容关系。保留注册，旧存档、旧物品和其他附属的引用继续可解析。
2. 先按明确证据归类现实口径和接口；`338` 显示覆写、Short / Medium / Long Ammo、占错语义插槽的配件进入待核验列表。
3. 另建立端游玩法别名：统一补给类别与抽象配件效果，同时记录偏离现实的地方及采用的 PUBG 版本。物资池优先显示统一条目，不要求删除其他原条目。
4. 分别核验“可供弹”“可装入槽位”“容量/换弹/属性生效”“模型和动画可显示”。几项结果独立记录，不能因为 JSON 白名单通过就一起标成兼容。
5. 只有明确证据支持的关系才批量应用；未知模型、专用底座和内置固定配件保留例外。确认总览表后再制作独立覆写与可回滚补丁，不直接把所有 `ammo` 或 `allow_attachments` 按名称全改。

这套做法能保留全部原内容，又让玩家在补给与配件选择时面对较少的类别。现实识别与游戏方便性可以同时存在，前提是每次合并都明确自己依据的是现实近似、端游规则，还是本模组主动做出的抽象。
