# 物品生成、区域编辑与拾取更新

日期：2026-10-17。适用环境：Minecraft 1.21.1、NeoForge 21.1.259、TaCZ 1.1.8-hotfix-r7。

2026-10-18 补充：TaCZ 枪械、弹药、配件及已保存概率条目在空中保留原版运动、采用固定朝向，真实落地后转为可 F 拾取的自定义小箱载体；0.22×0.13 格小箱保留重力，移除支撑后继续下落，模型边缘允许局部穿模。玩家掉落来源不会被 itemRespawn 清除。本文下方“普通丢出的 ItemEntity 不受影响”属于当时状态，当前规则以[小碰撞箱与停顿修复](恢复小碰撞箱与抛出停顿修复.md)为准。

本文按本轮确认后的规则说明。先前的“枪组”“按一匣拆分并保留余数”“128 个物资组”等设计已退出当前功能，只在旧存档迁移代码中保留读取兼容。

## 区域显示与木棍操作

- 已保存的可刷新地板显示蓝色透明覆盖，手持标记棒时强制显示。
- 白线只描临时选区的外围，共享边不绘制；不再给每一格画交叉网格。
- `/pubgdebug area add` 或快捷键保存成功后，两角立即清空并同步，白线消失。
- 对地板左键、右键仍分别设置两个角。对空气或没有方块目标时，使用下表操作。

| 默认操作 | 效果 |
| --- | --- |
| 左键 | 清除临时选区，不删除已保存的地板 |
| 右键 | 保存当前临时选区 |
| Shift＋右键 | 仅擦除当前框选范围内已经保存的地板；框外保留 |

快捷键可在 Minecraft 的“选项 → 控制 → 按键绑定 → 物资区域编辑”调整。原有 `/pubgdebug area add/remove/clearSelection` 指令保留。擦除导致区域分裂时，继续遵守原编号和稀有系数规则。

渲染改用 `RenderLevelStageEvent.AFTER_LEVEL`，在 Iris 最终合成后绘制到主目标；逐帧使用相机和投影矩阵，避免继承粒子阶段的目标／矩阵。覆盖关闭背面剔除并使用深度偏移。**没有启动游戏，尚未实机验证下落、下蹲及每一种光影。**

## 唯一物品配置

`/pubgdebug config` 的原物资组页面现在是“物品概率”：每一项是一种物品，包含预览、真实资产 ID、相对权重和数量范围。

- 自动加入当前 TaCZ 已加载的全部枪械、弹药、配件，包括第三方枪包提供的对应资产。
- 不自动加入制造材料、工作台、靶子、雕像、弹药箱等辅助物品。
- 不再限制 128 项；左栏使用原生滚轮与滚动条选择列表，并提供名称／ID 搜索。
- 同一 `kind + id` 只能出现一次。选择已存在物品会定位到原条目，不再创建重复行。
- 权重是相对值：A=20、B=10 时，A 的机会为 B 的两倍。权重 0 表示不参与独立抽取。
- 弹药初始独立权重全部为 0。新枪械／配件默认权重 1；已有配置的权重保留。
- ID 搜索、预览和 Tab 自动补全继续在物品选择器中提供。普通物品仍可手动添加；TaCZ 注册辅助项和通用空壳物品已从手动目录中过滤。
- 所有编辑仍是草稿，必须点击“保存全部”并收到服务端确认才生效。

每个刷新位置先按权重抽一种主物品，再按数量范围生成。生成主物品的预计数量仍为：

```text
已标记面积 × 区域稀有系数 × 物资密度
```

整数部分直接取用，小数部分按概率再加一件。默认密度 0.1，即每 10㎡ 预计一件主物品。近似平面继续独立应用数量设置、平面概率和间距；默认不再沿用 128 的每平面上限。配套弹药另算，不占主物品密度。

## 枪械的后置配弹

2026-10-19更新：先摆放所有主物品，然后给每把枪从三个配弹方案中抽一次。在“物品概率”选择枪后进入“配弹设置”，可逐方案修改弹种、组数、概率，以及该枪每组发数。

```text
三个默认方案：本枪弹药×1组／本枪弹药×2组／本枪弹药×3组
方案概率：步枪/冲锋枪/机枪30%／60%／10%，其他枪60%／30%／10%
每组发数：按枪类默认，可逐枪修改
```

| 枪类 | 默认每组发数 |
| --- | ---: |
| 步枪、冲锋枪、机枪 | 30 |
| 霰弹枪 | 10 |
| 狙击枪、DMR、手枪 | 15 |
| 火箭筒 | 1 |
| 榴弹发射器 | 3 |

三方案概率合计100%，仅抽一次；同枪各组使用抽中方案的同一弹种。此规则替换按弹匣容量向上取整的旧行为，详细JSON与迁移见[物品配置说明](枪组配置与全图刷新.md)。

配弹默认位于枪中心水平距离 **1–1.5 格**的环带内，最小／最大半径在“通用设置 → 间距与配套弹药”调整。只使用同一近似平面内已标记、可承托实际模型的地板，避免穿墙、悬空和物品重叠，不强制加载未加载区块。

如果整套主物品和配弹找不到合法位置，**该区域保留旧物资并报告失败原因**，不会悄悄丢弹、移出环带或只留下半套刷新结果。可以扩大标记地面、增大配弹半径或减少密度后重试。

`/pubgdebug itemRespawn` 仍刷新当前存档所有维度的全部已标记区域；未加载部分继续延后，任务使用提交时的配置和稀有系数快照。

## 尺寸、随机角度与贴地

- 有完整 3D 模型的枪械、子弹和配件，使用其正常掉落物的 `GROUND` 变换尺寸。
- 移除原先对所有枪额外施加的 `0.38` 缩放。
- 平面图标与很薄的独立模型保留额外 `0.38` 缩放。薄层判定：经过 GROUND 变换后的最薄轴不超过 0.04 格，且最薄轴／最长轴不超过 4%；判定含浮点边界容差。
- 没有可用 3D 模型才使用平放图标，不再把所有弹药强行变为二维。
- 每个主物品和每堆配弹分别取得 `[0°,360°)` 连续随机 Y 轴角度；角度保存到实体，重进世界不会不停旋转。
- 按实测模型边界平放、居中并抬高约 2mm。摆放、完整底面支撑、墙体碰撞和占地间隙按旋转后的范围检查。

客户端几何缓存随资源重载清除。服务端使用只包含数值的占地清单，不加载客户端模型类；本次清单覆盖已安装包的 424 枪械、78 弹药、245 配件。原包中少量失效引用使用图标或保守占地回退，详见 `logs/ground-loot-footprints-generation.json`。

后来添加或修改枪包模型后，可重新运行 `scripts/generate-ground-loot-footprints.py` 并构建，更新服务端数值清单。目录枚举本身自动完成；未知模型有保守回退，但不代表其真实边界已经验收。

## 选中与 F 键拾取

准星射线与随物品方向旋转的模型包围盒（OBB）相交后，高亮其模型轮廓。长枪的枪口、枪托均可选中，比最小包围球更贴近形状；包围盒仍是近似体，不逐三角面进行射线检测。

空**主手**时按 **F** 拾取选中的自定义物资；副手可以持物。只有 `GroundLootEntity` 受理该拾取，普通丢出的 `ItemEntity` 不受影响。原潜行右键拾取保留。

按键可在“TaCZ PUBG附属”分类更改。只有实际瞄准可拾取的物资并空主手时，F 才消费本次副手交换；其他场景保留原版操作。服务端重新核验来源、类型、距离、朝向、空主手及方块遮挡。背包只能装入一部分时，剩余数量保留在地面。

## 地图备份与命令补全

本轮新规则：**backup 仅保存方块和方块实体，例如箱子内容，不保存普通实体。restore 对新旧备份都只恢复地形／方块实体，不删除、重建或移动任何实体。** 旧备份的实体记录不再执行，历史文件不删除。

- `/pubgdebug backup map <地图编号>`：直接指定已创建地图，Tab 提供现有地图编号、名称和维度提示。
- `/pubgdebug restore <备份UUID>`：Tab 提供已有完整备份。
- `mapSelect`、`mapInfo`、`area info` 等使用现有编号的参数，也提供当前存档实际数据补全。
- 新建标签、数值和坐标保留自由输入；固定子命令由 Brigadier 提供补全。
- 备份向发起玩家显示进度条，扫描阶段与正式备份阶段分开显示；完成后提醒。完整规则见 [地图备份与复原](地图备份与复原.md)。

## 迁移与验证

旧世界配置会先保存 `.before-items-*.bak`，再迁移为 schemaVersion 2 的唯一物品表：重复物品合并，旧独立弹药权重置零，必要时对全部迁移权重同比缩放以保持相对比例。新增枪包目录补入时不改旧条目的用户设置。

配置没有人为条目数量上限；仍保留 8 MiB 网络传输预算和每区域 512 堆刷新事务预算，超出时明确报错，不截断配置或默默丢物品。这两个预算分别保护传输和服务器单次刷新负担。

示例石头 `examplemod:example_block` 和示例苹果 `examplemod:example_item` 的注册、资源、配方与掉落表已经删除，创造栏仅保留区域标记棒。历史存档中的这两个示例 ID 不再由模组注册。

修改前源码和说明备份：`logs/source-backups/feedback-items-20261017-230727/`。最终构建成功，4913 项纯逻辑断言通过，构建产物不含示例石头／苹果资源，自编说明的本地链接检查通过。记录见 [验证报告](../logs/feedback-items-report.json)和 `logs/feedback-items-build.log`。

验证只执行构建、纯逻辑检查和产物检查，**没有启动 Minecraft**。画面、所有光影、鼠标操作和真实多人仍需由用户实际使用反馈。旧配置迁移将在用户下次进入世界时执行，本轮没有直接迁移正在游玩的世界。

实现位置：`spawn/client/SpawnAreaClient`、`SpawnAreaKeys`、`lootconfig/LootConfigModel`、`LootConfigScreen`、`LootRespawnService`、`LootSpawnPlacement`、`lootspawn/client/Ground*`、`GroundLootPayloads`、`commands/PubgSuggestions`。新注册入口位于 `ExampleMod` 与 `ExampleModClient`。
