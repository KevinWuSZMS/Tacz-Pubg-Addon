## 1. 先分清四种数值

| 层次 | 内容 | 能否直接当作最终伤害 |
|---|---|---|
| 枪包原始基础值 | `GunData` / `bullet` JSON；未装外置附件的设计值 | 不能：距离表、模式增量、全局倍率仍要处理 |
| 当前模式基础缓存 | 当前 `fire_mode_adjust` 加到基础值，再乘相应服务器倍率 | 仅为下一层的起点 |
| 枪械缓存与运行时属性 | 已装附件、专属附件数据、事件、Lua、蓄力/过热等 | 仍需分弹丸、爆头、护甲等结算 |
| 实际生命扣除 | `Entity.hurt` 经护甲、效果、附魔、抗弹属性、吸收与事件后扣血 | 才是实际伤害 |

## 2. damage 是一发总基础伤害，多弹丸均分

默认 `shootOnce` 每个射击循环消耗一发弹药，并产生 `bullet_amount` 个子弹实体；每个实体调用 `applyShotgunDamageSpread(N)`，把伤害系数设为 `1/N`。因此通常的 `bullet.damage` 或当前距离段伤害 **D 是每发总基础伤害**，每颗弹丸为 `D/N`。不是 N 颗各打 D，也不是一次连发扳机的全部伤害：burst 会产生多次射击循环，每个循环重新消耗一发并生成 N 颗。

依据：[ModernKineticGunScriptAPI.shootOnce](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/item/ModernKineticGunScriptAPI.java:139)、[EntityKineticBullet.applyShotgunDamageSpread](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/EntityKineticBullet.java:224)。默认 N=1；Lua 可改运行时 N，独头弹标签 `tacz:intrinsic/slug` 可把 N 改为 1，见 [DefaultPropertyModification.modify](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/item/ModernKineticGunItem.java:296)。

每颗弹丸分别判定命中位置、爆头和护甲。全命中同一距离、同一部位且无防御时，N 颗总和仍为 D；散失部分弹丸、部分爆头或穿过不同目标时，不能用一次总伤害直接代替。护甲公式非线性，霰弹每颗小伤害分别减免，也不能把总 D 先减一次护甲再均分。

## 3. 距离伤害是阶梯表，非插值

`bullet.extra_damage.damage_adjust` 非空时完全替代 `bullet.damage`，每个区段加入当前模式的伤害增量，再乘 `DamageBaseMultiplier`；空表或没有表才使用 `bullet.damage`，其 Java 默认值为 5。

实际查找保持 JSON 列表顺序：命中点到弹丸发射起点的三维直线距离为 d，取第一个满足 `d < distance` 的区段。恰好等于阈值时进入后续区段，没有线性/样条插值，也不自动排序。不命中任何区段则伤害为 0；应以 `"distance": "infinite"` 收尾，该字符串解析为 `Float.MAX_VALUE`。当前 424 个候选均有 `extra_damage`，现有距离表的末项均为 `infinite`。

例如 `[{distance:30,damage:8},{distance:60,damage:6},{distance:"infinite",damage:4}]` 表示 d<30 为 8，30≤d<60 为 6，其后为 4。原始 `bullet.damage=10` 不再生效。当前 `suffuse:an94` 就有原始 damage 8.5、近距表首段 8 的区别。

`effective_range` 附件缓存只替换与首项原始阈值相等的阈值，并非按比例拉长整条衰减曲线。修改后也不重新排序，设置过大可能使后续段被首段遮住。飞行弯曲路径累计长度、射手命中时位置不参与距离伤害；但是速度、阻力、寿命会影响是否能飞到目标。

依据：[DamageModifier.initCache](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/resource/modifier/custom/DamageModifier.java:48)、[EntityKineticBullet.getDamage](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/EntityKineticBullet.java:516)、[EffectiveRangeModifier.initCache](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/resource/modifier/custom/EffectiveRangeModifier.java:40)、[DistanceDamagePairSerializer.deserialize](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/resource/serialize/DistanceDamagePairSerializer.java:12)。

## 4. 爆头、穿甲和实际伤害流程

普通枪弹每颗的流程为：距离/附件缓存 → 除以弹丸数 → 运行时 `damage` 属性修改 → 当次 `shotDamageMultiplier` → `EntityHurtByGunEvent.Pre` 可取消或改写 → 爆头倍率 → 普通/穿甲两段 `hurt` → Minecraft/NeoForge 防御与扣血。

爆头缓存为 `(基础头倍率 + 当前模式头倍率增量) × HeadShotBaseMultiplier`，再受附件/事件/Lua影响，构造弹丸时限制为 ≥0。`ExtraDamage` 对象内省略头倍率默认 1；但 **整个 extra_damage 缺省时 HeadShotModifier 的回退是 0**，不要误写成统一默认 1。当前 424 个候选不存在整个对象缺省，`cib:error` 刻意将头倍率设为 0。

头部命中不是“戴头盔就爆头”：服务器做弹道与实体命中位置判定。没有专用 `HeadShotAABB` 配置时，命中相对实体 Y 必须严格落在 `eyeHeight ±0.25` 内；姿势变化会改变眼高。见 [EntityUtil](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/util/EntityUtil.java:87)、[HeadShotModifier.initCache](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/resource/modifier/custom/HeadShotModifier.java:46)、[onHitEntity](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/EntityKineticBullet.java:393)。

令爆头等修正后的每颗伤害为 P，穿甲比 a 为 `(基础 armor_ignore + 当前模式增量) × ArmorIgnoreBaseMultiplier` 经附件等修改并夹到 [0,1]。先调用普通伤害 `P(1-a)`，再调用穿甲伤害 `Pa`。它不是减少目标 a 比例护甲值，也不是给伤害额外加 a 倍。`ArmorIgnoreBaseMultiplier` 修改的是比例，不是单独把穿甲伤害乘一次倍率。依据：[ArmorIgnoreModifier](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/resource/modifier/custom/ArmorIgnoreModifier.java:46)、[tacAttackEntity](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/EntityKineticBullet.java:575)。

仅考虑常规护甲 A 和韧性 T、无附魔/效果/特殊武器修正时，对普通那一段 q 使用：

```text
armor(q) = q × [1 - clamp(A - q/(2+T/4), 0.2A, 20)/25]
每颗实际伤害 = armor(P(1-a)) + Pa
```

真实流程还可受盾牌、抗性效果、保护附魔、其他模组事件、吸收生命/图腾等改变。穿甲段绕过护甲与其耐久消耗，仍不等于“真实伤害”。TaCZ 的 `tacz.bullet_resistance` 属性默认 0、范围 [0,1]，在 `LivingDamageEvent.Pre` 把属于 `tacz:bullets` 的伤害乘 `(1-resistance)`；它在护甲/魔法减免之后、吸收之前参与。普通/穿甲两段都会触发。见 [CombatRules](D:/HMCL-3.9.1/neoforge-mod-development/neoforge-1.21.1/minecraft-sources/net/minecraft/world/damagesource/CombatRules.java:17)、[LivingEntity.actuallyHurt](D:/HMCL-3.9.1/neoforge-mod-development/neoforge-1.21.1/minecraft-sources/net/minecraft/world/entity/LivingEntity.java:1785)、[EntityDamageEvent.onLivingHurt](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/event/EntityDamageEvent.java:16)、[ModAttributes](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/init/ModAttributes.java:13)。

## 5. 当前伤害类型与标签：不能照搬原版箭的规则

| 分支/伤害源 | 关键标签与含义 |
|---|---|
| 普通 `tacz:bullet` | `tacz:bullets`，scaling=never；不自动绕甲，不带 `is_projectile` |
| 穿甲 `tacz:bullet_ignore_armor` | 上述基础 + `bypasses_armor`；原版 `bypasses_shield` 递归包含该标签，所以穿甲段也绕盾 |
| void 两种枪弹 | 仍是 TaCZ bullets；额外 `bypasses_invulnerability`，其中 ignore_armor 版本再绕甲/盾；不是自动绕抗性/附魔 |
| `use_magic_damage_on` 目标 | 普通和穿甲源都换为原版 `indirect_magic`；原版绕甲/盾，不属于 TaCZ bullets，所以不走抗弹属性监听 |
| 爆炸 | 原版 explosion/player_explosion 类源，`is_explosion`；不自动继承枪弹的爆头、穿甲、抗弹标签 |

默认实体标签只有 `use_magic_damage_on` 含 `minecraft:enderman`；`use_void_damage_on` 和 `pretend_melee_damage_on` 为空。后者仅把 directCause 改为射手，并非直接把伤害改成原版近战。三者与 `fire_mode=auto/semi/burst` 无关：开火模式不改变这套伤害源选择。

固定 r7 与当前已扫描 mod/gunpack 资源未给四种 TaCZ 枪弹添加 `minecraft:is_projectile`、`bypasses_cooldown`、`bypasses_resistance`、`bypasses_enchantments`。因此弹射物保护不会仅凭“这是枪弹”就生效；普通保护通常仍可生效。原版盾可挡普通段，穿甲段通过 `#bypasses_armor` 继承绕盾。服务器数据包/其他模组可另改标签或事件，此处没有声称穷尽运行时注册器的全部行为。

来源：[createDamageSources](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/EntityKineticBullet.java:558)、[ModDamageTypes](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/init/ModDamageTypes.java:14)。TaCZ 资源在 `run/mods/tacz-neoforge-1.21.1-1.1.8-hotfix-r7.jar!data/.../damage_type/...`；原版递归标签在 [Minecraft 资源 jar](D:/HMCL-3.9.1/neoforge-mod-development/neoforge-1.21.1/build/moddev/artifacts/neoforge-21.1.259-client-extra-aka-minecraft-resources.jar) 的 `data/minecraft/tags/damage_type/`。

## 6. 受伤冷却、同 tick 多弹丸与爆炸例外

Minecraft 普通 `LivingEntity.hurt` 在 `invulnerableTime>10` 时，后续较小伤害通常被拒绝、较大伤害只补差值。TaCZ 在普通段、穿甲段前各把目标核心实体的 `invulnerableTime` 清 0，所以同 tick 的多弹丸会依次扣血。清的是受伤免疫计时，**不是**把显示受伤动画的 `hurtTime` 清零；红闪仍可能存在。没有“同一 tick 全部合并只取最大伤害”的 TaCZ 专用归并器。

这不绕过死亡、创造/无敌状态、盾牌、事件取消、效果等检查。多次独立伤害也可能逐次消耗吸收生命、触发图腾/其他模组逻辑；目标已经死亡时后续 `hurt` 会拒绝。结束后通常又有新的免疫计时，普通非枪伤害仍可能受其影响。见 [LivingEntity.hurt](D:/HMCL-3.9.1/neoforge-mod-development/neoforge-1.21.1/minecraft-sources/net/minecraft/world/entity/LivingEntity.java:1142)、[tacAttackEntity](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/EntityKineticBullet.java:575)。

启用爆炸的每颗弹丸还可独立触发一次爆炸，爆炸功率 **不除以 bullet_amount**。直接命中后，TaCZ 先清直接受害者免疫，再爆炸，所以直接命中可同时吃枪弹和爆炸；周围其他受害者没有逐一清免疫，连续爆炸是否累计仍受普通 `hurt` 冷却影响，不能把全体爆炸功率简单相加。

`ProjectileExplosion` 对 LivingEntity 固定碰撞箱的角点、面中心和中心共 15 点做遮挡射线，取可见点到爆心的最短距离 d。半径 R>0 时，伤害原始值为 `max(0,1-d/R) × explosion.damage × DamageBaseMultiplier`，再走原版爆炸源减免；完全被挡则跳过。它不是原版 TNT 的二次曲线，也不是 `2R` 的实际伤害半径。源代码虽把局部 radius 乘 2，但 strength 又乘 2，抵消后仍为 d/R。非生物实体用实体位置距离而非 15 点采样。R=0 不适合该计算，应避免设置。爆炸碰实体/方块可立即发生，也可能按 delay tick 倒计时；先过寿命则弹丸可能消失。

见 [ProjectileExplosion.explode](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/util/block/ProjectileExplosion.java:110)、[ExplodeUtil.createExplosion](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/util/ExplodeUtil.java:14)、[onBulletTick](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/EntityKineticBullet.java:292)、[onHitEntity 爆炸分支](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/EntityKineticBullet.java:454)。点燃还会引入后续火焰伤害，因此也要单独模拟。

## 7. 20 点生命下 BTK / TTK 的适用公式

20 点生命是 10 颗心。以下默认普通可受伤玩家，零护甲/韧性、无盾、无附魔/效果/吸收/抗弹属性、无回血/图腾、没有额外事件改伤，所射子弹均能飞到目标，且使用当前模式和实际倍率后的伤害。

令每发所中弹丸的实际伤害合计为 S，固定距离/部位且每发 S 相同：`BTK=ceil(20/S)`；S≤0 时没有有限 BTK。单弹丸身体 S=D，全部弹丸身体命中仍 S=D；若 N 颗中 k 身体、h 头部，且距离相同，则裸身 `S=(k+h×头倍率)×D/N`。每颗走不同区段则分别求和。

对普通连续射击、已准备好首发、恒定射速 R、不用换弹/拉栓/蓄力，名义射击 TTK 为 `(BTK-1) × floor(60000/R)/1000` 秒，R 必须使用服务器间隔逻辑得到的值。常见近似写法为 `(BTK-1)×60/R`，但会忽略整数毫秒截断。BTK=1 时此定义 TTK=0，只表示从首发到致死发的射击间隔为零；不表示命中无需飞行时间。

若从点击开始计算，需要另加首发等待、ADS/冲刺结束、蓄力、飞行及调度时间；若从首个命中开始计时，还要考虑末发与首发的飞行时间差。不要简单把所有步骤无条件相加：ADS/冷却等可能重叠。弹速/重力/阻力非零时，实际命中时刻应按弹丸轨迹算。50 ms 服务器 tick、网络和任务补偿也使名义数值不同于实测。

burst 每串 count 发，串内间隔 `floor(60000/bpm)` ms；串开始的服务端冷却依据 `min_interval` 秒，不是普通 rpm。简单理想排程可写为第 j 串第 k 发时间 `j×B+k×b`（j 从0，k=0..count-1），然后按实际命中累计到20；这是忽略任务 tick、手动输入、弹药与重叠串限制的排程模型，不能把它偷换成普通恒定 RPM。`continuous_shoot` 决定客户端可否持续触发连发。`CycleTaskHelper` 可以在一个 tick 补执行多次循环，不能一概把所有间隔向上取整成整 tick。

源码：[GunData.getShootInterval / getBurstShootInterval](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/resource/pojo/data/gun/GunData.java:302)、[LivingEntityShoot.getShootCoolDown](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/shooter/LivingEntityShoot.java:237)、[CycleTaskHelper](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/util/CycleTaskHelper.java:65)。服务端普通请求另有5 ms容差，不能把该容差当作保证更高射速。

示例：当前 `cbrg:beryl_m762` 在 51 格以内基础身体 D=8.8、头倍率2.35，当前倍率1且无外置附件。理想裸身身体 BTK=3；700RPM 普通连射名义 TTK 为 `2×85ms=0.170s`。全爆头每发20.68，BTK=1。爆头例子只表示命中头部后的伤害门槛，不包含压枪/散布的命中率。

单次对护甲的 BTK 计算须用上一节每颗公式，最终以每次 `hurt` 顺序推进状态。恰好位于整数发边界时，Java float 舍入可能影响结果；严谨工具应复现 float / 逐次扣血，而不是给显示四舍五入后的 D 做 ceil。

## 8. 可以调整哪些属性，单位和相互影响

### 后坐力：随机关键帧定义的是绝对偏移曲线

`recoil.pitch/yaw` 各为 `{time:秒,value:[下限,上限]}` 数组。每次开火在每帧区间内均匀抽一次值，乘后坐修正；补初始(0ms,0)，作者时刻转为 `time×1000+30ms`，用三次样条连接。消费时对玩家角度施加“当前样条值减上一样条值”的差，所以 value 单位是度、含义是这次后坐的累计/绝对偏移，**不是每帧再加一次该值，也不是角速度**。pitch正值通过减XRot抬枪；yaw符号决定左右。

从正值回落至0就是回正；负值会越过原点，不应因负号就拒绝。最后仍是正值则保留偏移，没有额外保证自动完全回正。三次样条可能超出关键帧数值范围。有效配置应保证每轴至少2个作者关键帧、时间严格递增且非负、value恰好2项且下限≤上限；r7注册只检查其中部分并排序，重复时间/点太少仍可能在生成样条时失败。连射会重建曲线并以新射击时间归零，不是无限叠加全部历史样条。

开镜缩放会降低摄像机后坐，趋向因子 `1/min(sqrt(zoom),1.5)`；趴下再乘 `crawl_recoil_multiplier`（默认0.5）；附件可分别改pitch/yaw。见 [GunRecoil.getSplineFunction](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/resource/pojo/data/gun/GunRecoil.java:58)、[CameraSetupEvent.initialCameraRecoil](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/client/event/CameraSetupEvent.java:167)、[applyCameraRecoil](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/client/event/CameraSetupEvent.java:209)。摄像机后坐与枪模动画不是同一组参数。

### 散布：接近角度标尺，但不是固定圆锥角

`inaccuracy` 类型为 stand / move / sneak / lie / aim，默认分别5 / 5.75 / 3.5 / 2.5 / 0.15。优先级是完整瞄准aim→趴下lie→蹲sneak→移动move→站stand；完整aim时不会再额外叠加move值。缺少的类型由默认表补齐。模式可分别加aim_inaccuracy/other_inaccuracy，附件与热量再影响。

默认弹道调用 MC `Projectile.getMovementToShoot`：标准化方向的X/Y/Z分别加三角随机数 `triangle(0,0.0172275×inaccuracy)`，再乘速度。该标尺在小角度下接近度，但**不是严格“半角为inaccuracy度的均匀圆锥”**；随机分布、最大偏角和散布半径不能直接当作该角度。`calcSpread` Lua可替换为自订二维散布，走 `(x,y,8)` 归一化方向，此时也不能套原版随机式。源码：[InaccuracyType](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/resource/pojo/data/gun/InaccuracyType.java:46)、[Projectile.getMovementToShoot](D:/HMCL-3.9.1/neoforge-mod-development/neoforge-1.21.1/minecraft-sources/net/minecraft/world/entity/projectile/Projectile.java:143)、[ModernKineticGunItem.doBulletSpread](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/item/ModernKineticGunItem.java:312)、[EntityKineticBullet.shoot 二维版本](D:/HMCL-3.9.1/neoforge-mod-development/logs/analysis-src/tacz-r7/com/tacz/guns/entity/EntityKineticBullet.java:359)。

## 9. 服务器配置与附件缓存

读取到的 `run/config/tacz-server.toml` 三个伤害系数均1、WeightSpeedMultiplier=0.015；`run/config/tacz-common.toml` 的 GlobalBulletSpeedModifier=2.0。r7把 ServerConfig 注册为 NeoForge SERVER 配置，因此真正运行时以该服务器/存档加载的配置为准；磁盘样本不等于运行时保证值。

普通数值修正组合的核心是 `(基础+Σaddend) × max(0,1+Σpercent) × Πmax(0,multiplier)`，之后还可执行附件表达式脚本。不是把每件percent依次相乘。缓存先初始化各基础值，再聚合附件修正；`AttachmentPropertyEvent`、KubeJS与Lua可继续改缓存，运行时 `modify_property` 可再改弹丸伤害/数量/速度等。后坐力使用参数化缓存，有自己的应用位置，不宜一概拿通用公式直接改原始关键帧。

改资产应通过数据资源重载并更新缓存/同步，不要只改已经生成的实体或直接写 GunData 后假定所有客户端同步。普通插件API可在 `AttachmentPropertyEvent` 内调整缓存；若直接改安装附件，需调用 `AttachmentPropertyManager.postChangeEvent` 更新射手缓存。资源中字段看似能改，不代表每个JSON路径都存在通用事件/GUI。
