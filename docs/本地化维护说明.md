# 显示文字与代码分离

玩家可见文字使用 Minecraft 原生语言资源。修改文案时，直接编辑以下两份 UTF-8 JSON：

- `neoforge-1.21.1/src/main/resources/assets/tacz_pubg/lang/zh_cn.json`：中文。
- `neoforge-1.21.1/src/main/resources/assets/tacz_pubg/lang/en_us.json`：英文，以及其他非中文语言的默认文案。

文件以可读的英文语义 key 对应显示文字，不使用数字行号作为 key，也不从 TSV 加载。示例：

```json
{
  "screen.tacz_pubg.map_editor.cancel_editing": "取消编辑",
  "screen.tacz_pubg.map_editor.discard_confirmation": "放弃本次地图编辑？",
  "screen.tacz_pubg.map_editor.reset_notice": "创建即备份整图；游戏开始前与结束后均恢复地形和容器内容。",
  "message.tacz_pubg.configuration.save_failed": "保存失败：%1$s"
}
```

相同 key 在英文文件中对应英文。`screen` 表示界面文字，`message` 表示提示和操作反馈，`error` 表示校验错误；后面依次是模组、功能和用途。原有物品、按键、死亡提示、gamerule 等遵循 Minecraft 自身的 key 命名。

只修改 JSON 的 value 不需要改 Java。两份文件的 key 必须一致。`%1$s`、`%2$s` 等是变量，翻译可以调整它们的位置，不能删掉；文本中的百分号写 `%%`。布局坐标、尺寸、配置字段、物品 ID、地图编号和命令参数继续由代码管理，不作为翻译 key。

`docs/localization-key-usage.json` 是可读的 key → Java 使用位置索引，便于从文案定位代码。它不保存另一份文案。

## 语言选择和刷新

简体中文使用 `zh_cn`。繁体中文、香港中文及其他中文变体先读取本模组的 `zh_cn`，再应用对应变体的资源包翻译；目前内置中文文案为简体。其他语言采用 Minecraft 的英文回退。没有修改原版游戏及其他模组的语言回退。

语言切换和资源包重载沿用原版流程，普通翻译仍支持资源包覆盖。已保存的用户地图名、预设名等按用户输入保留。历史版本已保存的普通提示文字也保留；后续新生成的状态会使用翻译引用。

## 代码用法

新的聊天、按钮和提示优先传原生组件：

```java
Texts.of("screen.tacz_pubg.map_editor.cancel_editing")
Texts.of("message.tacz_pubg.configuration.save_failed", reasonComponent)
```

它们最终是 `Component.translatableWithFallback`，英文回退取自 JSON。服务端发送组件时保留 key 和参数，每名玩家在自己的客户端解析语言。

`Texts.of` 保留原生 `Component`、数字、布尔值和字符串参数，将维度/物品 ID（`ResourceLocation`）、UUID、枚举等其他值转成字符串，空值显示为 `null`。Minecraft 的翻译组件不接受直接传入这些对象；统一转换避免地图/物资区域列表在创建提示时崩溃，也保证组件可以正常序列化。嵌套 `Texts.tr` 引用仍还原成组件，保留客户端语言切换能力。

旧代码中，校验结果、异常消息、持久化状态及部分自定义数据包仍使用 `String`。这些边界通过 `Texts.tr(key, args)` 保存与语言无关的引用，由 `Texts.component(value)` 在聊天/控件入口还原成原生组件；只有绘制、测量、搜索或填入输入框时才用 `Texts.resolve(value)` 得到当前语言的纯文字。不要在服务端调用 `resolve` 后向玩家发送结果。新增业务接口优先用 `Component`，避免继续扩展字符串适配层。

`assets/tacz_pubg/localization-index.json` 是旧 String 接口使用的内部传输索引，其短 ID 用于控制消息大小，不是维护文案的 key。常规修改文案不用碰它。新增 `Texts.tr` key 后运行校验脚本的 `--update-index`；已有索引 ID 应保持稳定，改名需同步修改其映射，以保留已保存状态的可读性。自定义配置反馈协议版本已更新，联机客户端和服务端需一起更新模组。

保存按钮和字段用途使用控件引用/字段标记判断，不依赖翻译后的按钮文字。生成高度接受 `world`、中文/英文名称以及当前资源包的显示名称。

## 维护检查

在工作区根目录运行：

```powershell
python scripts/verify_localization.py
python scripts/verify_localization.py --update-index --write-usage
.\neoforge-1.21.1\gradlew.bat -p neoforge-1.21.1 --console=plain localizationChecks
```

检查覆盖 JSON 重复 key、中英文 key 一致性、占位符、Java 引用、语言切换、原生组件保留 key、资源包覆盖、真实维度 ID 的地图/物资区域提示、参数类型转换、消息数据包往返、超长消息边界及中文变体回退策略。完整构建还运行现有地图、备份、物资和对局检查。检查不会启动游戏客户端或服务器；实际游戏中的布局和 mixin 加载仍需实机验证。

迁移前源码保存在 `logs/source-backups/localization-20261020-102628`。一次性提取、翻译中间文件和迁移脚本归档在 `logs/localization-migration`，不属于运行时语言资源，也不应重新覆盖后续人工修改。

参考：[NeoForge 1.21.1 国际化文档](https://docs.neoforged.net/docs/1.21.1/resources/client/i18n/)。
