# TaCZ 仿 PUBG 物资系统：当前统筹规划与逻辑树

更新：2026-10-17。Minecraft 1.21.1 / NeoForge 21.1.259 / TaCZ NeoForge r7 / **TaCZ PUBG Addon**（`tacz_pubg`）。本文已按当前独立物品规则重写，旧组合模板与方块实体备选设计不再作为当前实现；历史版本保存在 `logs/source-backups/feedback-items-20261017-230727/docs/`。本轮结果见[更新说明](物品生成与交互更新说明.md)。

## 已确定的核心规则

物资只在人工批准的地板集合内生成；图片或自动几何判断只提供参考，不代替室内核验。临时矩形可组合成真实非矩形、多层区域，保存稳定编号、维度、完整坐标、面积和稀有系数。

当前没有组合模板：配置唯一 `kind + id` 的独立物品、权重和数量。目录初始覆盖全部真实加载的 TaCZ gun/ammo/attachment，排除制造台、靶、箱等辅助物品；新增 gun/attachment 权重 1，独立 ammo 权重 0，没有 128 条业务上限。已有配置备份后迁移、去重，保留已有调整；新资产在每次服务器运行首次初始化存档配置时补入。

区域预计主物品数为 `有效面积 × 稀有系数 × 物资密度`，整数部分必出，小数部分做一次额外物品抽签；默认每 10㎡ 一个主物品。抽中什么按正权重物品的相对权重决定。区域稀有系数调数量，当前不额外给稀有枪加独立概率层。

先完成全部主物品，再按每把枪的真实弹药 ID 和基础弹匣容量补弹：`ceil(容量/30)` 份、每份 30 发，默认在枪水平距离 1～1.5 格内，范围可配。配弹不占密度名额。每个生成物品（包括每份配弹）独立采用连续 `[0°,360°)` 水平随机朝向；整个旋转模型要在已批准同平面上获得支撑、不穿墙、不重叠，放不下整区域失败并报告，旧物资保留。

## 射击游戏的一手资料与本项目设计的边界

PUBG 公开更新未提供完整服务端抽样代码、全量绝对概率表或通用室内识别算法；不能把我们自己设计的公式说成 PUBG 内部原算法。

| 一手资料 | 可参考的事实 | 本项目用途 |
| --- | --- | --- |
| [PUBG 16.2 更新](https://pubg.com/en/news/1717?category=patch_notes) | 不同地图、模式的物资分类调整不同，特殊地点可增加刷点 | 区分位置批准和物品概率 |
| [PUBG 22.2 更新](https://pubg.com/en-asia/news/4555?category=patch_notes) | P90 会附带至少 200 发弹药，不同模式调整武器和弹药刷新 | 参考枪弹配套；当前本模组30发份数公式仍是自定义 |
| [PUBG 24.1 更新](https://pubg.com/en/news/6359) | 特殊地点限制物资种类、质量，也存在室外刷新场景 | 首版室内白名单是我们的限制，不是PUBG所有地图规则 |
| [Epic Item Spawner](https://dev.epicgames.com/documentation/fortnite/using-item-spawner-devices-in-fortnite-creative?lang=en-US) | 作者布置生成设备、设置物品、随机与备用弹药 | 借鉴作者先定位置、再定生成规则的流程 |

公告“刷新率提高某百分比”通常是相对调整，不能直接作为某块地板出枪的绝对概率。当前物品权重表达抽取条件概率，面积密度表达预计主物品数量，两者分开。

## Xaero 导出底图能做什么

当前安装的 Xaero's World Map 1.47.0 支持 PNG 导出，[作者页面](https://modrinth.com/mod/xaeros-world-map)。本工作区此前只读检查 `PNGExporter`，确认原生文件名可带 `_x<originX>_z<originZ>` 原点，支持分图、局部导出和降采样，不能一概假定一像素等于一个方块。它保存渲染图片，不包含可直接批准全部楼层的三维房间结构。

因此底图适合标出建筑候选与 X/Z，不能单独决定地板 Y、屋顶下层数、家具净空或院子是否露天。人工在游戏里核验并用编辑棒批准才是当前实现；自动图片导入、室内识别和编辑器仍未实现，也不把 Xaero 作为必需前置。

若后续制作底图标注工具，应保留维度、地图版本、原文件名、原点、像素尺寸、X/Z每像素方块数、地图层、裁剪/旋转/缩放和已知坐标锚点。对于未旋转、未裁剪并已校准的底图：

```text
x = originX + (u + 0.5) × blocksPerPixelX
z = originZ + (v + 0.5) × blocksPerPixelZ
```

方块坐标用 `floor`（负坐标也一样）。降采样像素只能给候选范围，不能证明唯一刷点；有旋转时用至少三个不共线锚点校准。图片候选最终转为本附属独立数据，服务器无需依赖 Xaero 内部类。

自定义实体是当前载体，方块实体仅是早期研究过的备选，当前没有隐藏物资堆方块。原版 `LootTable` 可生成随机 ItemStack，却不会替我们识别房屋、摆地面模型、管理刷新轮次或拾取；这些由附属服务实现。

## 服务器权威与验证边界

客户端只负责预览和请求，服务端决定坐标是否合法、物品是否存在、配置版本是否过期、背包实际能接收多少。刷新事务预检完整区域后才替换原本附属物资，普通掉落物、玩家背包及其他模组实体不随物资刷新删除。未加载任务与配置快照存档，区块重载不补货；新一轮必须显式发起。

F 拾取仅限本附属地面载体，主手为空，副手可有物品，原潜行右键入口保留。TaCZ 枪械、弹药、配件的普通 ItemEntity 抛出后固定朝向，真实落地转换为同一地面载体，此后也能 F 拾取；空中和其他普通掉落物不走此路径。转换来源为 drop，刷新仅清理 respawn 来源，详见[落地转换方案](TaCZ掉落物落地转换方案.md)。共享模型状态必须复原，客户端资源重载清尺寸缓存，新增/修改枪包后更新服务端数值占地清单。

后续工作重点是实际对局层及地形变化系统，而非把圈配置存在就宣称已有完整缩圈与轰炸。默认只做构建、文件、依赖与必要纯逻辑检查，不主动启动游戏；界面、光影和多枪包实际观感待用户运行观察。本轮验证以[更新说明](物品生成与交互更新说明.md)为准。

地图备份复原已按最新决定限定为方块和方块实体：玩家、假人、动物、车辆、普通掉落物和本附属物资实体都不作为实体快照恢复。新旧备份复原均忽略历史实体记录，不执行旧版实体 UUID 审计、清理、重建或搬移；历史备份文件保留。物资重新生成仍使用独立的 `itemRespawn`，不能由地形复原代替。
