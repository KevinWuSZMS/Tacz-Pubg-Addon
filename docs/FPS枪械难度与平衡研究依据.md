# FPS 枪械难度与平衡：研究依据和建模方案

调查日期：2026-10-18，Asia/Shanghai。范围：当前工作区的 **424 个枪械候选 ID**；PUBG 对照限端游普通／排位。基础交战条件为 Minecraft **20 点生命、无护甲**，护甲作为补充情景另算。本文件只研究游戏参数和玩家操作，不讨论现实武器改装。

文献能支持瞄准的速度—准确率权衡、实验条件控制和武器之间的玩法取舍，但没有提供一条可以直接套到这 424 把枪上的公认“综合使用难度公式”。下文的分数、权重和方差收缩是本项目的可解释设计；它们需要与真实运行逻辑对应，不能称为已经通过玩家实验验证的难度。

前两篇关于 Fitts 的结论并不矛盾：受控目标获取任务拟合良好，不代表改变目标大小、奖励策略、玩家条件后仍可用同一套参数解释。以上资料均为原论文、作者资源或官方开发文章；下面的方差收缩公式由基本代数推导，不冒充某篇 FPS 论文的结论。

## 瞄准难度：可以借鉴 Fitts，但不能误用

常见 Shannon 形式为：

```text
ID = log2(1 + A / W)
MT = a + b × ID
```

`A` 为获取目标所需的移动距离，`W` 为沿移动方向的目标宽度，必须采用相容单位；`a、b` 需要由对应设备、任务和玩家的实验数据拟合。FPS 中可研究视角角距离与角宽度，但必须校准鼠标输入到视角变化的关系。[MacKenzie 的方法说明](https://www.yorku.ca/mack/hci1992.html)

这里的 `A` 不是“枪口到敌人的世界距离”。距离通过目标的投影大小、弹道和运动预测等路径影响交战。不能把射程或 JSON 里的散布数值直接塞进 `A/W`，再声称算出了玩家瞄准时间。吞吐量也需要实际操作时间及误差分布；只有枪械配置时，不能伪造人类 throughput。

对当前静态分析，建议把“目标获取”“开镜响应”“连续射击控制”“失误后的恢复”拆开。以后若采集玩家数据，再用目标大小、目标速度、转角、灵敏度及命中误差校准，而不是预先借用另一篇实验的 `a、b`。

## 先分清操作难度和武器强度

建议同时保存两条轴：

| 轴 | 回答的问题 | 建议展示的量 |
| --- | --- | --- |
| 操作难度代理 `D`，越高越难 | 在固定情景下，需要付出多少控制、等待、跟踪和纠错成本？ | 后坐力控制、散布、开镜响应、复射／换弹负担、失误惩罚，以及所采用的假设 |
| 杀伤与战斗效能 | 在命中条件成立时，造成伤害有多快，能持续多久？ | 单次有效伤害、击杀命中数 STK、理想 TTK、持续输出、弹匣续航、距离变化 |

高射速可能加重连续控制，也可能降低下一发等待；大伤害可能降低命中次数，同时仍要求准确的第一枪。一枪击杀的武器理想 TTK 为零，也可能十分难用。因此，不能简单规定“TTK 越低就越容易”或“RPM 越高就越难”。这里的拆分是我们的设计选择，与 PUBG 开发者强调的多维取舍相符。[SMG 官方开发分析](https://pubg.com/en/news/7426)、[DMR 官方开发分析](https://www.pubg.com/en/news/9000?category=dev_notes)

若综合分数包含 STK 或未命中代价，应明确它成为“在指定交战条件下完成击杀的难度代理”，不再是完全独立于伤害的纯操控分数。报告应同时保留各分项，避免强力但难控制的枪被一个总分掩盖。

## 20 点生命基准与 TTK 的边界

固定身体命中部位、距离、姿态、射击模式和无配件状态；无甲基准采用 `H = 20` 点生命，而不是 20 颗心。只有对规则发射、单发伤害固定且不需要换弹的简单武器，才可直接使用：

```text
STK = ceil(H / damage_per_hit)
shot_interval_seconds = 60 / effective_RPM
TTK_ideal = (STK - 1) × shot_interval_seconds
```

该式把第一发成功命中的时刻记作零。`STK = 1` 时 `TTK_ideal = 0`，不包含发现敌人、转身、开镜或弹丸飞行时间，也不表示可以无延迟获胜。可另外展示“准备＋射击＋弹道”的情景时间，但并行发生的过程不能不加说明地重复相加。

必须单独处理以下情况：

- 栓动、泵动、半自动点击上限、点射组间冷却、充能和脚本控制：从有效发射时序计算，不能只读取 RPM。
- 弹匣不能完成所需命中数：插入实际换弹或供弹时序；存在特殊装填机制时保留说明。
- 霰弹：全弹丸命中的总伤害只是理想上界，应区分单丸伤害、弹丸数和命中分布。
- 距离衰减、命中部位倍率、穿透或爆炸：分情景计算，避免用近距离身体伤害代表所有距离。
- 伤害不为正、字段缺失或脚本无法静态解析：保留候选 ID 并标为不可计算，不能填零或静默移除。
- Minecraft／TaCZ 的实际伤害结算、受伤间隔与附属改动：应以当前实现为准；上述连续时间理想式不自动证明它们在运行时没有影响。

补充护甲情景应使用实际 Minecraft／模组伤害结算及穿甲逻辑。除非实现确实如此，不能统一以固定减伤比例倒算“等效血量”。无甲与护甲结果分开展示，不混进一个未说明的平均值。

## 可解释的静态综合模型

建议先构造以下分项，再公开权重；它们是待校准的工程代理，不是研究论文给出的经验定律。

| 分项 | 可从配置／实现提取的候选量 | 需要避免的误判 |
| --- | --- | --- |
| 连续射击控制 | 固定发数／固定时间内的竖直补偿、水平偏移、恢复与首发冲击 | 可预测向上抬升与不可预测左右摆动不能只按同一个绝对值相加 |
| 视线扰动 | 相机后坐力、抖动、视觉恢复 | 屏幕晃动不等于子弹实际散布；应与命中方向的真实变化分栏 |
| 精度／跟踪要求 | 站立／移动／开镜散布，固定目标尺寸下的几何误差 | 较大散布不一定提高“手部瞄准难度”，但降低可靠性；可控与随机成本要标明 |
| 响应成本 | 开镜、收枪、切枪、移动惩罚 | 数值方向、单位、动画与实际可射击时刻需要核对 |
| 节奏与失误负担 | 复射间隔、装填、弹匣续航、打空后的恢复 | 理想 TTK=0 不能令低容错武器自动变成最容易 |
| 距离适应 | 弹丸飞行、衰减、固定目标运动下的提前量 | 不得把所有距离压成一个未经声明的默认距离 |

后坐力曲线需按实际插值、阻尼、随机项和运行时钳制解释，不能只取 JSON 数组第一个值。可以报告曲线积分、RMS、峰值或固定连射窗口的统计，但每项含义应保持一致。PUBG 官方更新也分别讨论竖直、水平、恢复和镜头扰动，说明这些不是可随意互换的一个数。[PUBG 31.1 官方更新](https://www.pubg.com/en/news/7582)

一个透明的初始形式是：

```text
z_ij = (g_j(x_ij) - baseline_center_j) / baseline_scale_j
D_i = Σ_j weight_j × z_ij
weight_j >= 0，Σ_j weight_j = 1
```

先把每个分项方向统一为“越大越难”。非负且长尾的量可采用 `log1p`；有符号后坐力、类别标签及缺失值不能机械套用。基准中心和尺度可以是调整前的均值／标准差，或适当的稳健尺度；零尺度分项不参与除法。应保存全部变换、单位、权重和来源。

**调整前后必须复用同一套冻结的中心、尺度和权重。** 若每次重算 z-score 都用新标准差，可能人为把分布重新拉回标准差 1，使“难度差缩小”的检验失效。对于本轮“同类比较”，可以冻结各类别的基准；但这样得到的分数不能未经校准直接比较不同类别。

不要把同一个机制以 RPM、每秒后坐力、总后坐力三个强相关量重复计分。至少提供权重敏感性分析：合理改变权重后，哪些枪的排序稳定，哪些只因权重选择而变化。缺项应显式降低置信度或分成单独可比集合，不能把未知当作优点。

## 严格保留类内排名的标准差收缩

对类别 `c` 的原始综合分数 `D_i`，令均值为 `mu_c`，选择 `0 < lambda_c < 1`：

```text
target_D_i = mu_c + lambda_c × (D_i - mu_c)
```

这是朝类别均值收缩的仿射变换，直接得到：

```text
mean(target_D) = mu_c
SD(target_D) = lambda_c × SD(D)
Var(target_D) = lambda_c² × Var(D)
target_D_i - target_D_k = lambda_c × (D_i - D_k)
```

所以严格大小关系和原有并列都保留；例如 `[2, 5, 8]` 取 `lambda=0.6` 后变为 `[3.2, 5, 6.8]`，标准差减少 40%。`lambda=0` 会消除严格排名，不能使用；单枪类别或原标准差为零无需收缩。计算保留完整精度，显示时四舍五入产生的视觉并列应与原有并列区分。

**只对分数执行这个变换，不会改变任何枪的实际使用体验。** 它只是规定目标。要实现“调整枪械后差异变小”，还要把目标反求到允许调整的游戏参数，再用同一模型重新计算。

建议的实现流程：

1. 冻结 424 个候选 ID、有效资源解析结果、类别、数据来源和调整前参数；为共享同一数据文件的多个 ID 建立关联。
2. 冻结场景、分项、归一化和权重，求出原分数及类内顺序；把真正相等的枪作为并列组。
3. 计算各类收缩目标。若用户没有指定收缩幅度，把 `lambda` 明确列为可调整设计参数，不伪称文献推荐值。
4. 优先小幅调整可解释的操控参数，如后坐力整体强度、散布或响应时间；保留曲线形状和武器身份。伤害、射速、弹丸数涉及强度与节奏，应单独说明，而不是为了凑总分随意修改。
5. 以“偏离原参数尽量小、实际分数尽量接近目标”为目标，在合法范围内求解；对原排序加入不逆序约束。共享资源只能一起调整，除非有明确且兼容的独立数据方案。
6. 从修改后的真实参数重新解析并算分，检查每类标准差、所有相邻顺序、并列组、约束和最大参数变化；不能只检查预先生成的目标分数。

可用的约束优化表达式如下，这是本项目推导的设计框架：

```text
minimize  Σ_i α_i × (D_i(theta_new) - target_D_i)²
        + β × parameter_change_cost(theta_new, theta_old)
subject to
  参数合法范围、最大允许变化、共享数据约束
  按原类内顺序保持 D_i(theta_new) <= D_(i+1)(theta_new)
  对原严格大小关系保留必要的正间隔；对原并列组保留并列约束
```

严格排名通常需要数值容差；间隔应依据原始差值设置，不给极近分数强加统一大间隔。非线性模型、离散参数、钳制、共享文件或参数上限可能令目标不可行。此时应减少收缩幅度并报告残差，不能偷偷颠倒顺序或剪裁分数来假装成功。

仿射目标保留类别均值，因此比原均值更易用的枪会适度变难，较难的枪会适度变易。如果希望只降低难枪的门槛，需要另设“仅降低难度”的单调变换并重新检验标准差；它不再自动满足上述均值与标准差公式。

## 424 把枪的 dotplot 应如何读

每个点代表一个候选 ID，按配置中的类别分面。外观变体和共享数据枪仍保留，另显示关联信息；未能计算的 ID 留在清单和缺失统计中。隐藏或特殊枪可标记，不能因不适合常规战斗就从“全部 424”中消失。

- 每个属性显示原单位及方向：伤害、RPM、毫秒、角度等分开作图；不要把不同量纲放在同一未解释的横轴。
- 调整前后使用同一横轴范围；横向坐标保持真实数值，重叠时仅沿非数值方向轻微错开，或使用透明度。
- 提供 ID、显示名、类别、原值、新值、差值、数据来源与缺失原因；大量点需要搜索或筛选。
- 同时显示原始属性图、分项图和综合分数图，避免仅凭一个难度点图掩盖强度变化。
- 汇总每类候选数、有效数、均值、标准差、标准差缩小比例、逆序数量、并列变化、最大参数改动和未达目标项。
- 本轮枚举全部候选时可用总体标准差 `ddof=0`，但前后必须一致；若另画样本置信区间，明确它对应玩家／模拟样本，不能给固定参数清单套上虚构误差条。

当属性跨度极大，可以另附对数轴图，但应保留零值和缺失的区别，并明确尺度。图表证明参数和模型分数的变化，不能单独证明玩家感觉更平衡。

## 本轮交付与后续验证边界

本轮可以完成静态参数盘点、可复算分数、按类别的 dotplot、受约束的调整方案以及类内排名／标准差检查。这里没有启动 Minecraft，也没有进行真人瞄准或实战性能实验。

以后若需要验证“更好上手”，可在另行安排的固定靶场记录目标尺寸、转角、运动速度、射击误差、完成时间和命中率，并分玩家水平比较；同时固定 FOV、鼠标灵敏度、配件、帧率和延迟。完美瞄准的假玩家适合验证伤害时序，无法直接代表人类操作难度。该实验设计借鉴 FPS 心理物理工具研究，不是当前已经执行的验证。[FirstPersonScience](https://arxiv.org/abs/2202.06429)、[Mouse Sensitivity 原论文](https://ieee-cog.org/2022/assets/papers/paper_64.pdf)
