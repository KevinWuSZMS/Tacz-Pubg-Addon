# 大地图实体扫描与跳过恢复

2026-10-22，续作“修复背包建模并接入物资”最近被中断的一轮大地图需求。

## 实体扫描

地图创建、开局准备和实体清理不再逐个加载矩形内的所有区块。后台先读取实际存在的实体区域文件位置表，检查有效记录是否含非空实体列表，再合并内存中可见或隐藏实体所在区块、原始实体最后位置以及本轮已归属实体的位置。只有这些候选区块进入区块加载和实体记录流程。

旧版尚未升级的地图仍兼容地形区域文件中的 `Level.Entities`。现代地形记录只读到版本头，不加载方块。索引为只读，使用独立后台线程；取消会在压缩读取和跳过过程中检查。服务器每次维护仍有 8 毫秒预算，并限制同时加载的区块数量，避免一次扫完整张地图。

真实密度测试还暴露了索引收尾的哈希冲突：`Set.copyOf` 对 packed 区块坐标创建的不可变集合发生大量碰撞，75% 密度下 30 秒无进展。线程采样已定位到 `ImmutableCollections.SetN.probe`，现改为只读封装原有 `LinkedHashSet`，避免重新放入该集合实现。定位证据保存在 `logs/entity-index-stall-thread-evidence-20261022.txt`。

## 大地图选择

新建地图面积超过阈值边长的平方时，先保护地图并等待实体选择。默认边长 500，即 250000 平方格；等于阈值不弹出。

- “是，我确认要记录地图中的所有实体。我明白这可能需要很久的时间记录或恢复。”
- “否，我无需记录这个地图中的实体”

关闭或选择“稍后选择”均保留待确认状态，重新打开地图后可继续选择；未选择前不能开始该地图的对局。选择“不记录”不扫描、不冻结、不清理、不还原地图实体，地形改动仍正常记录和恢复。选择与跳过决定写入存档，重启不会丢失。已有地图更改边界或进入编辑状态时保留原选择；已记录的地图改边界后重新建立对应范围的实体基线。

管理员可在 `config → 其他设置 → 战斗 HUD 与倒地救援` 的地图分类修改“大地图实体确认阈值边长（格）”。配置键为 `map.entity_recording_prompt_side_length`，只决定新地图的初始行为。

## 跳过命令

以下命令均要求 OP 2。省略地图编号时沿用现有地图命令定位规则。不带末尾 `confirm` 只显示说明和明确地图编号，不执行。

| 命令 | 行为 |
| --- | --- |
| `/pubgdebug map skipEntities [地图编号] confirm` | 跳过当前实体恢复，地形继续；实体记录过程中使用则终止记录，停用不完整基线并改为不记录实体 |
| `/pubgdebug map skipTerrain [地图编号] confirm` | 跳过当前地形恢复，实体继续 |
| `/pubgdebug map skipRestore [地图编号] confirm` | 跳过当前所有尚未完成的恢复 |
| `/pubgdebug map recordEntities [地图编号] confirm` | 保护或编辑状态下启用实体记录，建立新的完整基线 |
| `/pubgdebug map ignoreEntities [地图编号] confirm` | 保护或编辑状态下停用实体记录和后续实体恢复 |

跳过不会撤回已经完成的部分；未恢复部分保留当前世界状态。没有对应待处理内容、正在准备或运行对局时拒绝执行跳过。原地形、实体和归属记录保留；持久化成功后才取消任务，写入失败会恢复原状态。跳过标记只作用于当前恢复，下一局重新开始正常记录。

地形恢复始终从首次改动日志建立队列，只加载有改动记录的区块。未改动区块不会进入地形恢复队列。

## 实际计时方法

在独立 `run-entity-benchmark` GameTest 存档中生成四张 8192×8192 地图，每张 512×512＝262144 个区块。分别设置 0、65536、196608、262144 个区块各保存一个 marker 盔甲架。生成后独立重读全部地形和实体记录，断言区块数、实体数、每个选中区块恰好一个实体；未选中区块无实体。

计时使用实际 `EntityBaselineService`，包含磁盘索引、真实异步 FULL 区块加载、实体可用性等待、实体序列化与基线记录。GameTest 服务器本身无帧率限制，测试明确以每 50 毫秒一次的生产维护节奏调用，并保留 8 毫秒预算。每组最多测 30 秒；提前完成则记录实际总耗时，未完成则按已记录实体数线性外推。空白 FULL 地形和 marker 盔甲架是可复现的基准；真实地图、其他实体类型与服务器负载会改变结果。生成、断言读取及服务器启动时间单列，不算进扫描计时。

原始结果写入 `logs/large-map-entity-benchmark.json`，启动和逐组进度见同名 `.log`。测试有内部与外部超时，只会停止隔离测试进程，不会结束现有游戏或其他 Java 进程。

运行入口：先准备 `gradlew.bat --offline -PpubgInventoryGameTests -PpubgEntityBenchmark prepareGameTestServerRun`，再使用 `scripts/run-entity-baseline-benchmark.ps1`。夹具拒绝覆盖已存在的区域文件；重新运行应使用新的隔离测试存档。
